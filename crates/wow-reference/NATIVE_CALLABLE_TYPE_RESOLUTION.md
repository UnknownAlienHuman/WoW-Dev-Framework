# Selected native callable type resolution

`project_callables_with_type_resolution` adds one static Reference-owned overlay
to the genuine native callable signature. It uses the same exact document corpus
and selected environment as the original callable projection. The legacy
`project_callables` operation retains its original signature and generation bytes.

The overlay has its own `wow-reference/native-callable-type-resolution/1`
contract. It binds to the signature's exact Reference generation/view,
record key/digest and source ID. Its semantic inputs participate in the selected
generation identity. Original callable payloads, fields, order, inner types,
nilability, defaults, stride values, spans and restriction observations remain
unchanged and visible; original signature types remain qualified as
`original_source_type_identities_unresolved`.

The catalog contains only source-supported structure, enumeration and
ScriptObject owner declarations from the selected corpus/environment. Lookup
compares one supported atomic name exactly. A unique target gives a static
source-name association; multiple declarations remain ambiguous. Unsupported
composite syntax remains unsupported; missing names remain unresolved. There is no union/array
parser, alias inference, annotation syntax, `any` fallback or runtime type claim.
Targets retain original source identity and the correction disposition when a
reviewed widget owner is selected. Partial input cannot prove global absence.

An explicitly supplied `ValidatedCorrections` set is applied through the existing
source/value-guarded Reference correction engine. Effective tokens are separate
from original fields. Only an applied Type correction supplies an effective
token; expired, rejected, conflicting and not-applicable corrections keep their
original application outcomes. Evidence/reviewer strings are retained reviewed
input data, not proof of an external review or runtime observation.

The local native application selects this producer through its existing explicit
corrections resource. Omission and alias-only selection keep the legacy Reference
producer. The same validated correction set reaches Reference and annotations;
Service and Context never resolve names or reapply correction semantics.

The retained consumer is the Library producer input. New selected captures use
`wow-service/native-library-producer-input/2` and reopen from the exact retained
source/correction data through the selected producer. Version1 continues to
reconstruct the original producer, including older explicitly corrected inputs.
No store, Project replay layout or default EntityV1 profile changes are required.

Reference bounds and cancellation apply during catalog construction, application
and lookup. The existing ReferenceFacts Inspect/Build path borrows the sealed
signature and accounts its actual serialized bytes on the continuing Context
ledger. Rendering preserves owner output and cannot upgrade coverage, authority,
runtime legality, loaded state, Secret/protected behavior or annotation parity.

This selected functional scope does not close full Reference/E3 acceptance.
Current-source/Ketho/MCP comparison and runtime qualification remain the named
Tier X milestones in Issue #122 and the project completion matrix.
