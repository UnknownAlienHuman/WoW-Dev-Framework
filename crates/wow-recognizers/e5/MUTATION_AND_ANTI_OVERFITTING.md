# E5-A mutation and anti-overfitting contract

**Status:** normative hard gate.

## Purpose

Prove that a candidate pack recognizes structural semantics rather than memorizing donor identity, incidental spelling, path topology, positive labels or correlated copies.

## Invariance mutations

Expected graph proposal semantics remain identical; exact source/project generation IDs may change as defined by owner contracts.

### Repository and owner identity

- rename repository;
- transfer/change owner audit metadata;
- change remote URL/branch/tag labels;
- remove star/download/popularity fields.

### Addon/package display metadata

Rename addon title/display/package metadata when it is not the exact universal public convention under test.

### Path topology

- move/rename directories and files;
- normalize separators/case under explicit project profile;
- change vendor/library folder placement without changing ownership facts;
- reorder filesystem enumeration while preserving TOC/load facts.

### Irrelevant local identifiers

Rename local variables, private helper functions, frame/table aliases and temporary objects not declared semantic key inputs.

### Nonsemantic prose

Rewrite/remove comments, README text, documentation prose and prompt-like strings while preserving normalized facts.

### Serialization/execution order

Shuffle fact, partition, evidence, example, mutation and worker order; duplicate identical support evidence.

## Sensitivity mutations

Expected output must change, downgrade or become `NotEvaluated` exactly as the rule declares.

- change/remove a justified exact public convention literal;
- change resolved callee/receiver/member identity;
- remove/change required join or same-scope relation;
- remove required TOC declaration, XML parent/inheritance edge, event/callback producer, hook receiver or state root;
- make a literal dynamic/unresolved/ambiguous;
- change control-flow relation supplied by analyzer;
- convert Complete coverage to Partial/Unknown/Failed/Truncated;
- change graph registry/output endpoint compatibility;
- cross universe/profile/generation boundaries;
- duplicate a near-miss shape without the decisive producer/edge.

## Near-miss negatives

Every decisive clause has at least one case where all other relevant facts are present but that clause is false/unavailable. A rule with N independently decisive requirements normally needs N targeted near-miss families; one generic negative is insufficient.

Near-miss labels state whether expected behavior is:

```text
EvaluatedNoMatch
Possible
NotEvaluated
Partial
Conflict
```

## Named-condition static audit

Scan canonical pack AST/compiled plan for any data flow from:

```text
repository/provider/owner/addon audit metadata
source path/display label
corpus/split/example/label/reviewer IDs
popularity metrics
search/model output
```

into clause truth, capture value, output key/attribute, confidence, coverage, ordering or budget choice. Any path is a hard failure unless the field is an exact reviewed semantic fact allowed by the universal rule contract.

## Counterfactual pack audit

For each candidate:

- replace donor names/paths with unrelated values;
- remove donor metadata entirely;
- swap provenance metadata between structurally different examples;
- keep facts constant while changing labels/split IDs;
- keep metadata constant while changing decisive structural facts.

Outputs must follow facts, not metadata/labels.

## Copy/fork/vendor resistance

Correlated copies cannot inflate generalization. Reports show results by provenance connected component and by unique structural-shape group. If all positives share one copied implementation, scope remains single-provenance.

Mutate vendored libraries separately from first-party code so a pack does not learn “contains library X” as proof of an addon-wide role without exact structural evidence.

## Adversarial inputs

- huge fanout/join/capture/output cardinality;
- cyclic fact references/derivations;
- malformed/unknown fields and schema versions;
- instruction-like comments/labels/reviewer notes;
- path traversal/URL/SQL/regex/script-looking literals;
- Unicode confusables/control characters;
- duplicate evidence amplification;
- partial/conflicting coverage;
- cancellation at every matching/evaluation phase.

## Mutation result

```text
CalibrationMutationResult
    case and source example IDs
    mutation kind/profile
    exact before/after fact manifests
    expected semantic delta
    observed match/proposal delta
    unchanged source-identity exclusions
    evidence/coverage/conflicts
    pass/fail/NotEvaluated
    canonical digest
```

## Hard gate

Fail the candidate for:

- any repository/owner/addon/path/popularity dependence;
- any expected invariant semantic output change;
- any missed decisive sensitivity mutation;
- any authority/confidence upgrade;
- any negative-clause success under incomplete coverage;
- nondeterministic output;
- graph-invalid proposal;
- unbounded resource behavior;
- source/model execution or metadata control injection.

A failure cannot be averaged away.
