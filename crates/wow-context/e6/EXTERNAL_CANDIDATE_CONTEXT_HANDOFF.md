# `wow-context` E6-B external candidate exact-root handoff

**Status:** normative supporting seam; implementation not started.

## Purpose

Accept an exact owner root selected through E6-B while preventing external provider prose, rank, score, and inferred relations from becoming framework context facts.

## Input

The existing context request receives:

```text
exact ContextUniverseSet
exact project or Reference owner root
exact context intent/map/L0/L1/expansion/budget/tokenizer/privacy/license/renderer profiles
exact service operation/cancellation identity
```

It does not receive a provider client, external query, provider rank/score, unverified locator, or arbitrary provider summary as a semantic input.

## Handoff record

E6-B supplies a separately retained orchestration record containing:

```text
external result/candidate/artifact IDs
mapping receipt and exact mapped root
explicit selection receipt
external authority ceiling and nonclaims
external attachment disclosure decision
```

`wow-context` validates the mapped root and bound owner view. It need not interpret provider evidence to build canonical Project Map/L0/L1/context facts.

## External evidence attachment

In E6-B, external candidate evidence remains outside `ContextSemanticPack` framework facts. The outer service envelope may expose a bounded separately labelled attachment.

A future context profile could admit typed external Candidate items only through a new contract that preserves:

```text
provenance = semantic_candidate
confidence = Candidate
negative_authority = unavailable
```

No implicit support exists now.

## Exact-root validation

Validate:

- root resolves in the exact bound project/reference view;
- root universe/generation/profile equals the mapping receipt;
- selection receipt references that mapping/root;
- no provider field substitutes for owner identity;
- context profiles permit the root kind;
- source/privacy/license policies close.

Mismatch is rejected; no remapping or current refresh.

## Framework fact boundary

Canonical context facts derive only from exact project/graph/reference/source owner records. Provider text cannot:

- create identities, relations, aliases, lineage, replacement, migration, impact, or negative authority;
- assign roles/responsibilities;
- alter selection, expansion, budgets, privacy, renderer, or tool policy;
- become source documentation without exact owner/source mapping and policy;
- authorize edits/tools/runtime actions.

## Failure behavior

- invalid/missing root: fail/NotEvaluated;
- context owner unavailable: no provider-summary fallback;
- source disclosure denied: metadata/context may continue with explicit omission;
- partial/conflicted/truncated inputs: preserve exact state;
- cancellation: synchronous close, no background work;
- response loss: existing E3-C exact operation reconciliation.

## Output

`ContextSemanticPack` and renderings retain their existing IDs, evidence, coverage, conflicts, omissions, budgets, and source boundaries. They do not claim provider validation.

The E6-B outer envelope references both context result and external candidate/mapping/selection records separately.

## Tests

- exact project root;
- exact Reference root;
- mapping/root/generation mismatch;
- provider summary/rank/score inserted as framework fact;
- provider instruction text controls profiles/tools;
- denied external attachment with valid local context;
- context unavailable and forbidden snippet fallback;
- identical exact root from differently ordered provider results;
- privacy/license and source-boundary regressions.
