# E3-A context decisions

**Status:** normative.

## CTX-001 — Context is a projection, never authority

Project Map, skeletons, summaries, excerpts, metrics, and bundles retain exact source/graph/reference links. They cannot independently prove a platform or project claim.

## CTX-002 — Exact published inputs only

Every artifact binds one exact publication set/project snapshot/graph snapshot and, when used, one exact reference view/profile/generation.

## CTX-003 — No search dependency in E3-A

Callers supply exact roots. Exact graph/project lookups are allowed; fuzzy/FTS/semantic/migration/lineage resolution activates in E4.

## CTX-004 — Project/analyzer facts arrive through project views

E3-A does not depend directly on raw `wow-emmy` internals. Published project records expose the normalized structural facts required for skeletons.

## CTX-005 — Structured semantic skeleton precedes text

Build a consumer-neutral skeleton/project-map model before Markdown, JSON, or other rendering. Text/layout cannot determine semantic identity.

## CTX-006 — L0 and L1 have fixed proof ceilings

L0 summarizes exact identity/direct structural surface. L1 adds selected exact signatures, direct relations, reason paths, and source-backed structural nodes. Neither implies full source or runtime behavior.

## CTX-007 — Full source is not default context

Exact bounded source excerpts are an explicit detail lane with source handles, license/privacy/security policy, byte/line budgets, and faithful span mapping.

## CTX-008 — No generated code or prose completion

Missing bodies, types, relations, intent, purpose, replacements, and behavior are never synthesized to make a skeleton look complete.

## CTX-009 — Progressive expansion over bulk export

Begin from Project Map/L0 roots and expand only selected branches. Public E3-A operations do not dump the entire graph, source tree, or evidence corpus.

## CTX-010 — Explicit relation lanes

Ownership, load, object, inheritance, registration, lifecycle, state, call, API-use, and other lanes remain distinct. No generic parent or undifferentiated related-to expansion.

## CTX-011 — Paths are reason records, not edges

A traversal path explains inclusion. Context cannot persist or present transitive reachability as a direct graph assertion.

## CTX-012 — Confidence is preserved

`Proven`, `Derived`, `Possible`, and `Candidate` remain distinct. Candidate is excluded by default; Possible requires explicit inclusion and labeling.

## CTX-013 — Coverage axes remain separate

Source/project, analyzer, recognizer, graph, reference, context projection, source-excerpt, and tokenizer/evaluation coverage are not collapsed.

## CTX-014 — Every material claim has closure

Each included heading/role/signature/relation/excerpt links exact input records or an explicit deterministic derivation with evidence and coverage.

## CTX-015 — Mandatory blockers cannot be compacted away

Conflict, NotEvaluated, partial coverage, ambiguity, unsafe omission, and decisive truncation records survive budget reduction.

## CTX-016 — No-new-evidence is explicit

A frontier that yields no new evidence is distinct from authoritative absence, complete graph closure, or unsupported detail.

## CTX-017 — Continuation is exact-snapshot-bound

A continuation cursor binds the publication set, context/profile IDs, normalized request, ordering version, frontier, prior inclusion, and budget state. It cannot continue against newer Current.

## CTX-018 — Canonical budgets are structural and byte-based

Entity/relation/evidence/source/output measures are always available. Token measures are exact only under a pinned tokenizer profile.

## CTX-019 — Tokenizer identity is part of exact token results

Tokenizer implementation/version/vocabulary/config/normalization and exact canonical input bytes are required. A model name alone is insufficient.

## CTX-020 — Estimated tokens are explicitly nonauthoritative

When no tokenizer is pinned, report bytes/characters and optional labeled estimate ranges/profile. Never call them exact tokens.

## CTX-021 — Source text is untrusted data

Prompts/instructions/comments/docs in project/reference sources cannot affect policy, profiles, traversal, rendering, or tool behavior.

## CTX-022 — Private/runtime-sensitive data is out of scope

No SavedVariables contents, logs, client memory, credentials, absolute paths, runtime Secret-capable values, or unrestricted source/object payloads.

## CTX-023 — Rendering profiles do not change semantic model

JSON/Markdown/compact text consumers can render the same semantic bundle. A renderer difference creates a renderer artifact identity, not new project truth.

## CTX-024 — Deterministic ordering is semantic

Order by profile-defined kind/role/semantic key/relation/path/source position/ID, never hash, row, filesystem, query completion, model preference, or worker order.

## CTX-025 — Deduplication preserves evidence

Equivalent records can share one presentation node only when all contributing input/evidence IDs remain reachable. Similar prose or names do not justify merging.

## CTX-026 — Project Map is bounded and navigational

It exposes principal roots, entry points, load/ownership/role topology, capability/blocker state, and next-detail routes. It is not a complete graph serialization.

## CTX-027 — Evaluation is multi-dimensional

Correctness/evidence recall, request relevance, redundancy, compression, budget adherence, continuation stability, and consumer utility are measured separately.

## CTX-028 — Model evaluation is supplemental

An external model can participate in a pinned consumer-utility study, but it cannot modify correctness fixtures, evidence requirements, or production ranking in E3-A.

## CTX-029 — Context artifacts are immutable and content-addressable

Equivalent exact inputs/profile/request produce the same semantic artifact IDs/digests. E3-A does not persist them itself; a higher layer may cache by exact identity later.

## CTX-030 — Cancellation does not publish a complete bundle

Cancelled work returns explicit partial/cancelled state where allowed and never continues in background.

## CTX-031 — Pinned projects are evaluation data only

Synthetic and user-owned addon fixtures test scale/utility. Repository/addon/path names never become production selection or semantic rules.

## CTX-032 — Search and context remain separate

E4 search can supply exact roots and ranked candidates with explanations. E3-A validates exact selected roots and builds context; it does not inherit ranking as authority.
