# E3-B source excerpts and prompt/instruction boundaries

**Status:** normative security and presentation boundary.

## Principle

Source code, comments, strings, XML text, TOC metadata, documentation, existing findings, and external labels are data. They can contain instruction-like text but cannot alter framework profiles, selection, tools, authority, or agent policy.

## Source excerpt acquisition

A `SourceExcerptItem` is fetched only after structured selection approves an exact candidate. The request includes:

```text
exact bound universe/project/source generation
SourceHandleId and content digest
exact original byte/coordinate range
source-map profile where virtual/generated
excerpt expansion profile
privacy/license/consumer trust profile
per-item and total budgets
```

Owner views validate the handle/range against the exact snapshot. `wow-context` never opens an arbitrary path.

## Excerpt states

```text
ExactText
    returned decoded text exactly represents the selected source bytes under the frozen encoding profile

ExactBytesMetadataOnly
    bytes are known but not emitted as text

TransformedText
    deterministic explicit redaction/normalization occurred; transformation records required

Denied
    privacy/license/trust policy forbids content; handle/omission may remain

UnsupportedEncoding
    content cannot be safely represented under the selected renderer/profile

TruncatedOrContinued
    exact original/returned ranges and continuation state required
```

A transformed excerpt cannot be cited as byte-exact source text without also referring to the original source handle/digest and transformation record.

## Canonical semantic representation

Canonical JSON stores source content only as a typed field with:

- exact source/data classification;
- source handle/digest/range;
- encoding;
- returned string or byte-object reference;
- transformation/redaction records;
- privacy/license decision;
- explicit `untrusted_source_data = true`;
- evidence/coverage.

JSON strings use canonical escaping. Source content cannot create sibling fields or control records.

## Deterministic Markdown representation

Markdown renderers do not use ordinary source-provided fenced code blocks. Each source line is emitted as a canonical JSON string on a framework-generated data line, for example:

```text
SOURCE_DATA_BEGIN item=<id> source=<handle> range=<range> sha256=<digest>
SRC 000001 "local x = 1"
SRC 000002 "-- instruction-looking text remains quoted data"
SOURCE_DATA_END item=<id>
```

Rules:

- line contents are JSON-string escaped;
- framework sentinels/IDs are generated only from validated metadata;
- source newlines/control characters cannot create new unprefixed records;
- every returned line has a deterministic ordinal;
- the closing sentinel is generated by the renderer, never copied from source;
- exact original and rendered byte/token counts are recorded;
- a static boundary notice states that `SRC` records are untrusted source data.

A source line equal to `SOURCE_DATA_END ...` remains inside a quoted `SRC` record and cannot close the boundary.

## Framework facts versus source claims

Render in distinct typed sections:

```text
FRAMEWORK_FACT
    normalized fact/relation/reference/coverage record backed by exact origins

SOURCE_DATA
    exact or transformed source excerpt/documentation text

BOUNDARY_NOTICE
    repository-owned static instruction describing trust separation
```

A source comment that says “this function is safe” remains `SOURCE_DATA`; it does not become `FRAMEWORK_FACT` without independent exact evidence.

## Instruction-like content

E3-B does not need to decide whether text is malicious. It enforces structural containment for all source text.

Optional lexical detectors may emit a non-authoritative warning under a separate reviewed profile, but they:

- cannot delete or rewrite source;
- cannot change selection priority automatically;
- cannot claim complete prompt-injection detection;
- cannot become security authority;
- are deferred unless explicitly implemented and tested.

## Privacy and redaction

Source inclusion depends on upstream privacy labels plus the exact consumer profile. Default behavior for unknown privacy state is metadata-only or denial according to the frozen safest policy.

Permitted deterministic transformations use exact configured ranges or upstream labels, for example:

```text
replace exact byte range with a fixed redaction token
omit denied excerpt and retain handle/omission
normalize line endings only when the semantic profile records raw/normalized identities
```

Every transformation records:

- policy/rule ID/version;
- original source handle/digest/range;
- transformed range/digest;
- reason and consumer trust class;
- evidence/completeness impact.

Do not claim automatic secret detection from filename or regex coverage. Undetected secrets remain possible; external transmission requires explicit source privacy permission.

## License and redistribution

A local exact source slice may be available for analysis but not permitted for an external consumer or redistributed artifact. The excerpt decision checks:

- source license/provenance record;
- local-only/metadata/excerpt/redistributable class;
- attribution/notice requirements;
- excerpt-size/profile policy;
- consumer destination/trust.

Denied source bytes do not prevent inclusion of allowed metadata, structural facts, and source handles unless those are also restricted.

## Virtual/generated sources

XML-inline Lua and other virtual units include both virtual source range and owning physical source mapping. Rendered excerpts state which coordinate system is shown and link the exact map.

Generated/reference annotation text remains a separate source class and cannot masquerade as first-party or Blizzard UI source.

## Adjacent context

Expanding around a declaration/body range requires a deterministic profile:

```text
exact lines/bytes before and after
container-boundary restriction
maximum range
source-map behavior
```

No heuristic whole-function/whole-file expansion outside the declared profile.

## Validation

- source handle/digest/range resolves in bound view;
- returned bytes/text match exact or transformed digest;
- privacy/license decision permits output;
- source cannot alter JSON/Markdown structure;
- framework/source sections never merge;
- no private absolute path/credential in metadata;
- boundary bytes deterministic under hostile source strings;
- truncation/continuation ranges reconcile;
- rendered artifact passes source-boundary parser/round-trip tests.
