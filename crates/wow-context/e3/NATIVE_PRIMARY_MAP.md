# Native primary Project Maps

This is the first executable subset of E3-B, tracked by
[Issue #122](https://github.com/UnknownAlienHuman/WoW-Dev-Framework/issues/122).
It is a bounded projection of genuine retained project/graph owners, with an
explicit exact configured Reference view. Full E3-B acceptance remains pending.

The original closed profile is `wow-context/primary-direct-navigation/1`. Its
canonical bytes and navigation shape remain unchanged. Its
[descriptor](../../wow-service/e3/native-primary-map/profile.json), request and
service envelope are frozen with [checksums](../../wow-service/e3/native-primary-map/CHECKSUMS.json).
These are synthetic native-owner fixtures; they do not attest Gethe, Ketho or a
WoW client. Historical E3 examples describe the broader target and are not
implemented runtime aliases.

`bind_context_universe_set` checks the acquired Project/Graph source context,
configured Reference generation and explicit caller ProfileIdentity. ReferenceView
has no intrinsic ProfileIdentity: this association is recorded as
`exact_configured_generation_and_explicit_caller_profile`, without inventing
source/profile attestation. Blizzard UI platform projects refuse in both profiles.

For `primary-direct-navigation/1`, an exact graph node is the navigation root.
Both profiles read the original edges in both directions:
`contains`, `defines`, `depends_on`, `optional_depends_on`, `owns`, `loads` and
`loads_before` edges, with Candidate confidence preserved. Native node/edge IDs
determine ordering. The original project container is retained separately; an
ordinary primary source graph does not supply a project-container graph node.

The selected `wow-context/primary-project-navigation/1` profile uses the acquired
ProjectId and original immutable ProjectSourceOrigin as its container root.
An explicit project root must match that ProjectId; only this profile allows an
omitted root, resolved by service after acquisition. No graph project node or
contains edge is synthesized.

Every genuine retained source-file projection is a mandatory navigation root,
joined to its original source proposal/support and actual final published node.
The map schema is `wow-context/project-map/primary-project-navigation/1`; its
`navigation` has schema `wow-context/project-navigation/1`, exact `project_id`,
`source_file_roots` and one native `neighborhoods` view per root. Roots are ordered
by native node ID. `root_enumeration=complete_for_retained_primary_source_files`
describes this retained projection, not complete filesystem or corpus coverage.

Each neighborhood preserves its own native query, counts, coverage and truncation.
Node/edge support selection deduplicates exact IDs, while the original views remain
distinct. For project navigation, the `direct_navigation_prefix` omission sums
native per-query omissions, not distinct omitted edges across the project.

The application obtains native neighbors and resolved explanations using the
acquired pair's sealed immutable graph read. `prepare_project_map` checks the
direct selection; `primary_project_navigation_queries`, neighborhood admission
and `prepare_primary_project_map` check the complete project-root batch.
`build_project_map` requires full original support,
evidence and source-handle closure for every selected node and edge. Source and
package/TOC/load custody come from existing owners. The map never reparses source,
executes source, invents graph edges, substitutes a root or upgrades confidence.
Graph queries reuse validation; native acquisition itself still reconstructs and
validates the retained owners.

The immutable artifact exposes `project_map_id`, canonical bytes and a read view.
Its identity binds exact universe, descriptor, root, bounds, native selection,
support, custody, coverage and omissions. Metadata bounds include mandatory
identity/evidence/coverage/conflict/omission records. Mandatory content that does
not fit refuses; native truncation remains explicit. All project file roots and
their custody must fit the full aggregate work/metadata budget: no first-file or
root-prefix fallback is returned. Native adjacency scan work is reserved for the
whole root batch before execution; each view and resolved receipt is admitted
cumulatively. Native per-query limits remain separate from these aggregate guards.
The sealed navigation request passes its actual remaining metadata allowance and
already-reserved logical scan scope to graph before batch materialization. Graph
checks cumulative encoded output before collector/index or edge/node growth;
Context still charges every genuine returned view against the same ledger. This
does not reserve the sum of per-query maxima or charge scan work twice. The batch
uses one physical edge scan while preserving original per-root logical counters.
Work is finite and cancellable.
The service additionally reserves the combined encoded Reference, graph and
evidence-catalog inputs before its one necessary catalog copy. Encoded accounting
is not an OS peak-memory measurement.

Every result is Partial or Truncated, with `absence_authoritative=false`.
Omissions record optional platform exclusion, unenumerated broader navigation,
L0/L1, packs/rendering and unavailable exact token accounting. No source bodies,
host paths, continuation, complete-corpus or runtime safety claim is emitted.

The frozen direct-profile fixture publishes and reopens a real native pair,
verifies actual direct nodes/edges and original producer/evidence receipts, repeats exact
bytes, updates Current, and checks stale/mixed/missing/budget/cancellation refusal.
Selected frozen bytes and actual Windows CLI delivery complement this fixture;
fault-close injection, mid-operation cancellation, ordering/worker campaigns,
package corpus, full E3-B and required Tier X qualification remain pending.

The [project-profile fixture](../../wow-service/e3/native-primary-project-map/README.md)
freezes its reviewed descriptor/request/envelope separately. Two actual physical
files retain both roots, four native edges and ten deduplicated support receipts.
Its focused lifecycle checks explicit/derived project roots, exact repeat bytes,
per-query truncation with all roots retained, and aggregate-budget refusal.

L0/L1, expansion, semantic packs, JSON/Markdown rendering, excerpts, exact tokens,
continuation, platform/combined maps and their qualification are still required
by the full E3 contract. A working navigation map does not close those obligations.
