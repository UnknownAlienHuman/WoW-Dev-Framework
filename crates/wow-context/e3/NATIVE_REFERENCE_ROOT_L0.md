# Exact native Reference-root L0

The selected owner profile is `wow-context/primary-reference-root-l0/1`, with
schema `wow-context/l0-skeleton/primary-reference-root/1`. Its compatibility
consumer is combined ReferenceFacts Both Inspect/Build under
[#128](https://github.com/UnknownAlienHuman/WoW-Dev-Framework/issues/128) and
the canonical implementation lane [#122](https://github.com/UnknownAlienHuman/WoW-Dev-Framework/issues/122).
This is a navigation identity for one API root, not a container membership
projection. ContainersV1 and StateRootV1 retain their existing eligibility.

The owner requires an exact `native_api_callable` root of the held detail map.
It uses the existing Reference facet validator to qualify the accepted producer
assertion/final node, bound Reference profile/generation/view, exact API record
key/digest, original ReferencePack handle and PlatformSource/Proven
SourceObservation evidence. The genuine native callable signature binding is
validated by that same engine. Inert origin inputs cannot attest this custody.
Missing, mixed, duplicate or incompatible associations refuse.

L0 serializes the exact node, assertion, Reference partition/coverage, record
key/digest, original source/evidence and one explicit detail route to that root.
It includes no Reference payload or signature/type observations. Direct member
and relation arrays are empty; member enumeration and API-root children remain
NotEvaluated. No implicit parent, inferred container, accepted cross-universe
link, source body, type resolution or runtime claim is added. The original map
preserves its support, coverage, conflicts and scoped omissions unchanged.
Partial/Truncated states and `absence_authoritative=false` remain mandatory.

`build_primary_reference_root_l0_skeleton` exposes this typed owner over exact
native inputs. Combined `CombinedPrimaryInspection::ReferenceFactsBoth` invokes
the same engine before existing ReferenceFacts L1, with the same held map/root
and construction Budget. The original public `ReferenceFacts { root, origins }`
selection remains L1-only. The combined service request uses the existing
ReferenceFacts L1 profile with `level="both"`; explicit L0 and L1 selectors still
cannot coexist. No new top-level combined/pack/renderer/request schema is needed:
the new serialized responsibility is isolated by its own L0 profile/schema.

Both L0 and L1 validation work, original joins, retained metadata, identity,
pack/rendering and final delivery consume the continuing allowance. Mandatory
overflow and cancellation fail conservatively; checked reverse owner closure
precedes Service delivery. Existing L1-only/omitted and container/state bytes
are preserved through an absent optional `reference_root` field.

Functional, exact-head build verification and broad Tier A/X/runtime acceptance
are separate states recorded in the canonical Issues; this contract itself
asserts no successful gate.
