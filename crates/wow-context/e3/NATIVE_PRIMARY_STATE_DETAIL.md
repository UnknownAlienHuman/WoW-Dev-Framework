# Native Primary state-detail L1

This closed selected inspection profile is tracked in
[#122](https://github.com/UnknownAlienHuman/WoW-Dev-Framework/issues/122).
The bounded native source-absent lifecycle and Windows CLI byte checks pass;
full E3-B/Tier A/X acceptance remains open.
The broader [L1 state contract](L1_SKELETON.md#state) remains normative.

## Exact selection and original metadata

Profile `wow-context/primary-state-detail-l1/1` emits
`wow-context/l1-skeleton/primary-state-detail/1`. Its frozen descriptor is
[profile.json](native-state-detail/profile.json).
The first consumer requires explicit non-frontier inspect L1 and an exact
GraphEntity for an original ordinary selected-TOC state_root or state_path.
Project, L0/Both, other root kinds, build and frontier selections refuse.
Omission/default still selects `wow-context/primary-l1/1`.

StateRoot rows retain original ProjectGraphStateRoot plus every exact supporting
ProjectGraphStateDeclaration, including repeated TOC rows/ordinals,
account/character scope, ambiguity and source/evidence support pairs.
StatePath rows retain original ProjectGraphStatePath, exact root_id and ordered
typed literal keys. A path's required root and supporting declarations must be
present in the same admitted neighborhood; missing/truncated custody refuses.
No first-declaration selection or same-name root substitution is allowed.

Original native direct nodes/edges, callable/Lua/XML metadata where captured,
confidence, source handles/digests/spans and applicable TOC/load custody remain.
The profile retains Both direction, depth 1 and the 27 reviewed native relation
kinds from the default detail map. Metadata adds no graph node, inferred edge,
wider traversal or runtime field. Native unrelated truncation/omissions remain
scoped and visible; Partial/Truncated never establishes authoritative absence.

## Native construction and custody

`PrimaryL1Profile::{EntityV1,StateDetailV1}` is the closed owner selection;
`PRIMARY_STATE_DETAIL_L1_PROFILE` names the selected descriptor.
`build_primary_l1_skeletons_with_profile(universe, map, graph, root, profile, stop)`
returns the existing immutable PrimarySkeletons via the native L1 engine.
It binds the same ContextUniverseSet, map and acquired GraphPartitionRead.
Original provenance proposals resolve to exact accepted native nodes through
GraphPartitionRead::published_entity; typed rows and their support stay native.
Decoded JSON, source reparsing or a second producer cannot supply that authority.

One owner Budget covers selected joins, original records/support/custody,
ordering, identity and the complete immutable output, with cancellation.
Required native root/path/declaration/support failure refuses rather than
returning an empty successful facet. Mandatory byte/work overflow also refuses.
The immutable result's `remaining_metadata_bytes()` reports the actual allowance
after construction for the selected service envelope; it is not a new budget.

## Inspect consumer and compatibility

[Inspect](../../../apps/wow/CONTEXT_INSPECT.md#selected-native-state-detail-l1)
uses `--level l1 --l1-profile-id wow-context/primary-state-detail-l1/1` and an
exact `--root graph-entity@<base64url-id>`. ContextL1Profile and
ContextInspectRequest::with_l1_profile select this route; profile/frontier
composition refuses independently of builder order. One native acquisition,
existing Current/Reference guards and checked resource closure remain.

The selected request and nested L1 identity bind the explicit profile. Default
requests/artifacts and original direct graph bytes stay unchanged; no producer,
registry, project configuration, storage or replay version is introduced.
The selected final envelope fits the actual remaining allowance after immutable
construction, retaining the same cumulative ledger. It cannot reset limits or
drop mandatory evidence to fit. Build/frontier consumption of this profile is
unsupported in this first route.

This is generic static state metadata. No values, loaded state, combat safety,
API parity, current-source qualification, bodies or exhaustive-field claim is
added. Coverage remains Partial/Truncated with `absence_authoritative=false`;
original uncertainty, conflicts and omissions remain explicit.
