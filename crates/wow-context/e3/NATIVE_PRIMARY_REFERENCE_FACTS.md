# Native Primary Reference-facts L1

This closed selected contract extends bounded native inspection and structural
pack/render consumption under [#122](https://github.com/UnknownAlienHuman/WoW-Dev-Framework/issues/122).
The broader [L1 API/Reference contract](L1_SKELETON.md#apireference-facts) remains
normative. This page records the selected scope, not full E3-B/Tier A/X acceptance.

## Explicit selection

`PrimaryL1Profile::ReferenceFactsV1` selects
`wow-context/primary-reference-facts-l1/1` and emits
`wow-context/l1-skeleton/primary-reference-facts/1`. Only explicit non-frontier
L1 with an exact Primary GraphEntity is supported. Project roots, L0/Both and
frontier composition refuse; no API node or record is selected by name.

Combined Inspect/Build additionally supports ReferenceFacts Both through the
[Reference-root L0 owner](NATIVE_REFERENCE_ROOT_L0.md). That selection requires
an exact accepted `native_api_callable` root and places its navigation identity
before original ReferenceFacts L1 on the same detail map and continuing Budget.
The standalone L1 route and its bytes remain unchanged.

The acquired ordinary publication must genuinely select
`native_api_uses=reference_v1`. Retained source-absent reopening requalifies the
original native Library/API/call owners; decoded endpoint data cannot replace
that proof. The complete host Reference profile/view must equal the held native
Reference, independently of optional caller guards.

[Inspect](../../../apps/wow/CONTEXT_INSPECT.md#selected-native-reference-facts-l1)
uses `--level l1 --l1-profile-id wow-context/primary-reference-facts-l1/1` and
`--root graph-entity@<base64url-id>`.
[Build](../../../apps/wow/CONTEXT_BUILD.md#selected-native-reference-facts-l1-pack)
uses the same selection with `wow-context/primary-structural-pack/1` and its
existing optional structural JSON/Markdown renderers.

## Original record, source normalization and accepted support

The held native API proof supplies original assertion/source/evidence inputs
only for API nodes selected by the exact local map.
`ReferenceOriginInput::new(&GraphAssertionRef, &SourceHandle, &EvidenceRecord)`
is inert borrowed data, never graph or source authority. The context validator
requires the same bound universe/map and acquired GraphPartitionRead, original
producer batch/proposal and accepted final node membership.

Every selected native API association binds all five original identity fields:
`reference_profile_id`, `reference_generation_id`, `reference_digest`,
`record_key` and `record_digest`. Exact Reference lookup and bounded original
record digest validation must agree. The source handle must be an original
ReferencePack handle for the bound Reference generation, with its origin ID in
that record's source_ids; accepted proposal support and original
PlatformSource/Proven SourceObservation evidence must agree exactly. Mandatory
missing, mixed or conflicting custody refuses; no same-name or first-record
substitution is permitted.

Each facet retains the original ReferenceRecord, key/digest, source IDs and
restriction facets; exact accepted assertion/final node; original handle,
evidence and Reference partition coverage. Unknown original raw fields remain
in the original canonical record payload, which stays opaque data to context.

The genuine `NativeViewProjection::callable_signature(record, stop)` handoff
supplies a `NativeCallableSignature` minted by the Reference owner's retained
catalog during native projection. Its original Reference generation/view digest,
record key/digest and source ID must match the accepted association. No public
constructor or decoded annotation sidecar can mint this typed owner result.
The selected L1 validates that binding before retaining the observations.

The observations preserve the existing source normalizer's ordered parameters
and returns, original names and type_name identities, optional inner_type,
tri-state nilable, original raw default/stride_index values and source spans.
Missing nilability stays missing, distinct from explicit false and true. Raw
values retain their original kind/value/span; context does not evaluate them or
turn a default/stride observation into runtime values or inferred optionality.
An empty projected return list does not assert runtime no-return behavior.

The original types remain qualified as `original_source_type_identities_unresolved`.
An explicitly selected native corrections producer can additionally supply the
Reference-owned [exact-name type overlay](../../wow-reference/NATIVE_CALLABLE_TYPE_RESOLUTION.md).
Context retains that typed sibling unchanged under the same signature binding;
it does not resolve names or apply corrections. The same explicit corrections
selection can additionally retain the existing annotation emitter's callable
type-token and optional-marker observations. A private bounded catalog captures
the already-computed renderer result at emission; it does not lower again or
parse generated text. `NativeCallableBindings::callable_lowering` supplies one
inert validated Core observation with exact native source/Reference/artifact/map
descriptors, ordered lanes/ordinals and original/generated ranges.

Context admits that data only with a genuine `ProjectLibraryFileView` qualified
against the sole Library snapshot already admitted by this Project. It checks
Reference/source/Project/Library binding, original signature member spans and
exact emitted token and `?` bytes, including final UTF-8 range geometry. A supplied
mismatch refuses; genuine missing emission remains absent/NotEvaluated. The file
view does not serialize source bodies or become an annotation producer receipt.
The facet labels `annotation_producer_custody=NotEvaluated`: artifact/map IDs
remain supplied descriptors, and exact Library token agreement does not validate
those IDs or prove that the supplied lowering came from that producer.
This is emitted analysis syntax, not complete type resolution or consumer semantic
proof. Broader restriction interpretation and runtime qualification remain unevaluated.
Context does not import annotations/emmy, parse the record payload,
interpret restriction prose, widen unknown types, add restrictions or infer API
legality. JSON and Markdown retain the original record and typed observations
under their existing canonical/escaping and trace rules; rendering cannot
upgrade authority.

## Selected callable alias dependencies

The Annotation owner captures exact input-name associations during its existing
type-lowering pass and retains only the projected aliases used by those names
and their direct alias dependency closure. Array and union syntax remains the
emitter's responsibility. Context receives the admitted observation and at most
one additional verified Project Library alias file. It checks each input atom,
alias declaration range and type-expression bytes against those held files
under the continuing construction Budget; it neither parses nor resolves types.

Alias definitions retain their independent resource revision, relative path,
digest and source span with `source_scope=annotation_alias_catalog`. They are
external annotation overlay data, separate from the original Blizzard signature
and Reference atomic-type catalog. Missing, rejected, duplicate and cyclic alias
definitions are not admitted as resolved facts. No selected alias is proof of
complete inventory, producer custody, consumer type semantics or runtime safety.
The optional typed fields are omitted when empty; NativeLibrary serialization,
Reference identities and retained producer-input/1 and /2 remain unchanged.
