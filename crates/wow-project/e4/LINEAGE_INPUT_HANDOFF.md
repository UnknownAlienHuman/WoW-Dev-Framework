# E4-B project and Blizzard UI lineage input handoff

**Status:** normative supporting seam. `wow-project` supplies exact generation-bound facts; `wow-graph` owns lineage assertions.

## Output purpose

For one exact published project or Blizzard UI source generation, expose the minimum typed records required to compare it with another exact generation.

```text
PublishedProjectView / BlizzardUiProjectView
-> exact LineageEndpoint records
-> exact source/project stable-ID and transition records
-> deterministic structural fingerprint records
-> exact project-use and graph relation handles
-> coverage/conflict/privacy/license manifests
```

No cross-generation conclusion is produced here.

## `ProjectLineageInputView`

```text
ProjectLineageInputView
    exact ProjectStore/PublicationSet/ProjectGeneration/ProjectSnapshot IDs
    exact GraphGeneration/GraphSnapshot IDs
    project kind/universe/profile/build/flavor/channel
    source snapshot/content/root/file/package/TOC/XML/load manifests
    analyzer/recognizer profile and fact manifests
    entity/source/relation registry versions
    owner read catalog
    capability/coverage/conflict/privacy/license manifests
    canonical digest
```

For E3-A Blizzard UI source, include exact source materializer/repository commit/tree/content/build-binding/license identities and the `SkeletonInputView`/fingerprint profiles. Provider labels remain provenance, not continuity authority.

## Endpoint records

Each exported endpoint includes:

- exact generation-local graph entity key/ID and kind;
- project/source owner IDs;
- canonical identifiers and source location;
- package/TOC/load unit/order roles;
- declaration/source handle/span and virtual-to-physical map where applicable;
- signature/type/member/facet records from the exact analyzer/source pipeline;
- direct owner/containment/load/object/inheritance/registration/state/call/API-use relation handles;
- recognizer role assertions with original producer/confidence;
- evidence/provenance/coverage/conflicts;
- privacy/license class.

It contains no whole source body by default.

## Stable project/source identity

A field can be exported as stable identity evidence only when `wow-project` owns a frozen identity contract proving its stability across the compared generation family.

Not stable by default:

```text
display name
relative or absolute path
line/byte offset
TOC order
file content digest
function body digest
repository/branch/tag name
provider build label
```

These remain exact generation-local facts or candidate features.

Potential owner-defined stable records require explicit namespace/profile/version, for example a canonical persisted project entity ID produced from an owner-declared stable source identity scheme. Absence of such a scheme is not repaired by E4-B.

## Explicit source transition records

`wow-project` may export exact reviewed transition records generated by an owner/tooling process that explicitly names both endpoints and relation scope. It must retain:

```text
transition kind
exact from/to generations and endpoints
producer/profile/version
source evidence and derivation
applicability/cardinality
coverage/conflicts
```

A Git rename heuristic, same blob hash, or provider-generated move list is Candidate/Derived only according to its frozen evidence profile; it is not automatically explicit owner identity.

## Structural fingerprints

E2-C/E3-A deterministic fingerprints can expose bounded typed features:

```text
entity kind and owner role
canonical signature/type facets
normalized declaration structure
exact direct relation-kind neighborhood facets
source package/load/TOC/XML context
literal/static registration/state/API-use facets
content/semantic digest classes
```

Fingerprints:

- bind exact generation/profile/schema;
- preserve unknown/unsupported/loss records;
- exclude private paths/source bodies where policy requires;
- are matching evidence, never entity identity;
- cannot contain model summaries or named-addon production heuristics.

## Project-use records for migration/impact

Expose exact use sites through public bounded views:

```text
resolved API/type/event/template/mixin/function target
source handle/span
operation/call/registration/hook/state/use shape
owner/package/load/context relations
analyzer/recognizer/rule producer identities
confidence/provenance/coverage/conflicts
existing finding/evidence refs when requested
```

Dynamic/unresolved targets remain Possible/NotEvaluated. No second parser in lineage code.

## Removal inventory coverage

For E4-B removal/introduction gates, project/source view reports exact closed inventory capabilities by:

```text
configured roots
package/TOC variant
file/unit/entity kind
analyzer/recognizer/graph partition
source decoding and coordinate mapping
```

A complete file manifest does not imply complete semantic entity coverage. Missing/failed/unsupported partitions remain explicit.

## Cross-generation update history

E4-B compares final exact snapshots. Project watcher order, mtime, cache history, or Git event sequence is nonauthority. When exact owner transition records are absent, final-state facts generate candidates only.

## Source and runtime boundary

Project/Blizzard source can establish exact static implementation/use facts for its pinned bytes. It cannot establish:

- public API contract or restriction by itself;
- runtime load success/readiness;
- event delivery/payload accessibility;
- current Secret Value state;
- taint/combat/protected legality;
- performance;
- user-visible behavior.

These requirements remain distinct owner/runtime evidence.

## Privacy/license

- stable source handles replace private absolute roots;
- source bytes are not included unless exact downstream privacy/license policy permits an excerpt;
- local indexing does not grant redistribution;
- unknown license/privacy blocks external source output, not necessarily metadata/fact handles;
- provider/repository credentials never enter the view.

## Dependency rule

`wow-project` does not depend on E4-B APIs. It publishes a narrow owner view/artifact under its own contract. `wow-service` acquires exact views; `wow-graph` validates the supplied records.

## Validation

- every record belongs to the exact publication/generation;
- no source/project/reference universe collapse;
- stable-ID records use an explicit owner contract;
- fingerprints are bounded and loss-declared;
- all relation/source/evidence handles resolve;
- coverage supports claimed inventory scope;
- no runtime/API authority upgrade;
- no whole-source/private data leak;
- deterministic output under reordered storage/source traversal.
