# Ordinary Primary callable replay

**Status:** partial executable #122 compatibility contract. Focused native
capture/hydrate/recapture, ordinary publication, source-absent context acquisition
and update/removal pass. This family reuses native physical project owners.

## Named family and exact admission

| Consumer | Exact contract |
|---|---|
| Files transport | `wow-service/local-primary-callables-files/1` |
| Native replay envelope | `wow-project/native-project-replay/primary-callables/1` |
| Stored replay record | `wow-project.live-replay.primary-callables.v1` |
| Public project catalog | `wow_project::replay::publication::STORAGE_SCHEMAS_PRIMARY_CALLABLES_V1` |

The exact catalog contains the named stored replay and existing
`wow-project.live-pair.v1`; it is registered independently in
STORAGE_SCHEMA_CATALOGS. Prior catalog memberships/epochs are not widened.
Declaration-only, signature-only and combined selection use this same family,
with exact choices retained in configuration.

Admission requires ordinary Fixture/Repository physical Main plus exact separate
Library snapshots and function-call analysis. At least one configuration recipe
must be selected: PhysicalFunctionDeclarationRecipe::DeclaredSyntaxV1 and/or
PhysicalFunctionSignatureRecipe::IndexedTypesV1. There is no selected TOC,
package/Main plan, retained platform, package XML binding, platform graph,
XML classification or candidate. DeclaredSyntaxAndBodyShapeV1 is outside this
closed family, even though another native family supports that enum variant.

## Identity, strict replay and native authority

Existing optional physical_function_declarations and physical_function_signatures
configuration fields bind configuration digest and project-generation derivation.
Omitted fields preserve the old None bytes/recipes. Presence selects the named
Primary envelope; an empty selected envelope cannot downgrade to ordinary /4.
Present recipe fields decode as supported non-null enums, with unknown/duplicate
fields and explicit null refused. A recognized but ineligible recipe/configuration
combination refuses admission rather than falling back to a platform family.

Capture retains exact Main source and independent Library inputs/identities,
configuration, analyzer binding/report identities and generation inputs under
existing aggregate bounds. Hydration reconstructs genuine configuration/workspaces,
runs the existing native publisher/analyzer and compares the recaptured owner
identities. It does not deserialize declaration/signature observations into
analyzer authority. Source-absent reopen uses those retained inputs rather than
reopening the former host files or reparsing a decoded report.

The configuration's exact selections must match the report recipe. Signature
observations remain conditional analyzer results: supported fragments, empty
resolved returns and Partial/Unavailable states are preserved. The unselected
context facet stays NotSelected. Selection changes identity, not the evidence
ceiling: declarations are syntactic, indexed types are not runtime contracts,
and no body-shape or semantic-equivalence claim is added.

## Ordinary publication and reopen

ProjectPublicationBundle and AcquiredProjectPair use the existing native replay
and exact source-proposal/graph-pair validation. Ordinary service creation chooses
the matching catalog, publication performs inactive readback before guarded
Current activation, and reopen admits the exact registered old/new catalog.
A mismatched catalog or replay/configuration identity refuses; an old epoch is
not automatically migrated, widened or relabeled. No new namespace/platform
selection document or public command is needed for this ordinary family.

The [files input](../../apps/wow/PRIMARY_CALLABLE_INPUT.md) feeds existing
wow project publish/read. Existing context inspect/build acquires the immutable
pair and retains original declaration/signature recipe, observation/support,
coverage and omissions. New selection does not make context Complete or prove
source/load/runtime absence. Old unselected input/replay/store routes remain
separate and unchanged. No new limits or source refresh is implied.

The focused project and service tests retain exact source/configuration/report
identities, original context support and prior-generation reads. Old None /4 and
frozen legacy physical/TOC/package archives remain admitted; old catalogs refuse
the new records without changing Current. Malformed selections and cancellation
refuse. Detailed checkpoint evidence belongs to the canonical Issue; broader
acceptance remains open under
[#122](https://github.com/UnknownAlienHuman/WoW-Dev-Framework/issues/122).
