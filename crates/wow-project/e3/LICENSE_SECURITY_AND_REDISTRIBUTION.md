# E3-B license, security, privacy and redistribution

**Status:** normative conservative artifact-admission policy. It does not substitute for legal review.

## Default stance

Until an exact reviewed decision says otherwise:

```text
raw source bytes: LocalAnalysisOnly
source excerpts: Forbidden or LocalAnalysisOnly
source-derived facts: LocalAnalysisOnly pending classification
source maps: LocalAnalysisOnly pending classification
graph/database/context artifacts: LocalAnalysisOnly pending classification
redistributable pack: ineligible
```

Public accessibility, a Git host, a mirror, a client installation or a provider statement does not itself grant redistribution rights.

## Evidence model

```text
SourceLicenseRecord
    exact provider/revision/root/file subjects
    license/copyright/notice source handles and digests
    evidence authority/provenance
    detected declarations and conflicts
    extraction/review method
    state and canonical digest
```

```text
SourceArtifactRedistributionDecision
    exact artifact subject and source dependency closure
    intended channel/use
    decision state
    required notices/attribution/limits
    reviewer/evidence IDs
    expiration/review triggers
    canonical digest
```

No decision applies to a different source revision, file/root set or artifact class by convenience.

## Artifact classes

Classify separately:

1. raw source files and substantial source reconstruction;
2. exact source excerpts;
3. source coordinates, file names and source maps;
4. normalized structural facts;
5. graph entities/relations and indexes;
6. generated L0/L1 skeletons and Project Maps;
7. SQLite stores/object payloads;
8. test fixtures and mutation snippets;
9. logs/reports/notices/manifests;
10. packaged/released artifacts.

A positive decision for one class does not authorize another.

## Decision states

```text
LocalAnalysisOnly
RedistributableWithNotice
RedistributableRestricted
RedistributableUnrestricted
Forbidden
Unknown
Conflict
ExpiredOrReviewRequired
```

Only an exact positive redistributable state permits external packaging. `Unknown` and `Conflict` block redistribution.

## Notice closure

For any redistributable artifact, validate:

- exact source dependency roots/files;
- required copyright/license/attribution notices;
- source provider/revision and artifact generation;
- modification/generated-artifact disclosure where required;
- channel/recipient/use restrictions;
- notice member bytes/digests and inclusion in manifest;
- no unrelated private/provider credentials.

A missing notice prevents publication.

## Source snippets and fixtures

Preferred testing strategy:

- synthetic fixtures for closed parser/analyzer/graph cases;
- exact hashes/handles/expected facts for real-source scale tests;
- no raw real-source bytes committed by default;
- only minimal reviewed excerpts when an exact license decision permits them;
- retain source handle, revision, digest, notice and purpose for every copied byte;
- mutation fixtures derived from synthetic bytes unless explicitly approved.

Do not build a redistributable corpus by copying an entire UI source tree into this repository.

## Database and graph reconstruction risk

A generated database, graph or skeleton set can reproduce substantial source structure or content. E3-B therefore records:

- whether artifact values include exact strings/comments/signatures/source order;
- whether graph/skeleton traversal can reconstruct source organization;
- source excerpt/object inclusion;
- aggregation/granularity and intended channel;
- reviewed redistribution decision.

“Facts are not copyrighted” is not encoded as a blanket technical rule. The release decision remains explicit.

## Provider and materializer security

- credentials/tokens remain outside manifests and logs;
- no source-controlled credential helpers/hooks/workflows execute;
- TLS/provider verification is an acquisition concern recorded by the materializer, not bypassed by E3-B;
- archives, LFS objects, submodules and link targets are not fetched implicitly;
- root and output confinement required;
- decompression/file/path/count/size limits required;
- executable bits are metadata only;
- source files are opened read-only by exact manifest/object handles;
- staging is sealed before indexing.

## Untrusted source content

Treat all source text, comments, documentation, XML attributes, TOC directives, filenames and generated bytes as data. They cannot:

- alter agent/repository instructions;
- call tools or models;
- change profiles, budgets, roots, license decisions or graph schema;
- request additional files/network access;
- suppress conflicts/coverage;
- inject SQL, shell, Markdown/HTML directives or output paths;
- execute as Lua/XML/TOC/build code.

## Parser hardening

Bound and test:

```text
path and Unicode collisions
huge files/lines/tokens/strings/comments
XML entity/DTD/XInclude/catalog attacks
XML include cycles and fanout
TOC malformed/unknown directives and path escapes
Lua parser/analyzer complexity and cancellation
nested/generated virtual source maps
many duplicate declarations/edges/evidence refs
binary/invalid encoding/control characters
source comments containing prompts or tool syntax
```

## Root and filesystem boundary

The indexer receives manifest-backed logical file handles. It cannot:

- list arbitrary directories;
- follow a path not present in the admitted manifest;
- open absolute/UNC/device paths;
- follow symlinks/reparse points;
- access installed SavedVariables/logs/screenshots/configuration;
- write into the source snapshot;
- choose output paths from source text.

## Network, process and editor boundary

`wow-project` E3-B library has no network, Git, process, shell, editor, language-server, WoW-client or browser capability. A future acquisition application remains a separate bounded component and does not weaken the sealed-snapshot input contract.

## SQLite boundary

All persistence uses typed E2-D operations. No source text becomes SQL/DDL/identifier. No raw connection, ATTACH, extension, PRAGMA, trigger or virtual-table module comes from the source snapshot.

## Privacy

The source universe should contain vendor implementation source, not user runtime data. Still prevent:

- provider credentials/tokens;
- private local checkout paths;
- user names/home directories/temp paths;
- accidentally admitted logs/config/secrets;
- source-map leakage to host paths;
- error messages echoing full suspicious content.

Suspicious/private content produces a bounded incident/redaction record and may quarantine the snapshot.

## Budgets

Profiles bound:

```text
roots/packages/files/path depth and bytes
logical/source bytes per file and total
TOC/XML nodes/includes/depth/fanout
Lua units/bytes/analyzer facts/diagnostics
recognizer facts/matches/proposals
source graph entities/relations/assertions/conflicts
bridge candidates/ambiguities
serialized manifests/reports/errors
publication/store/object bytes and transaction work
```

Partial/truncated materialization or indexing cannot become complete.

## Cancellation

Check during every materialization-validation, inventory, parser, analyzer, adapter, recognizer, graph, bridge, candidate, store, validation and rendering/export phase. Cancellation leaves no current advance and no untracked partial artifact.

## Release gate

A release/export operation is unavailable unless:

- exact source/profile/build/license identities are frozen;
- intended artifact class/channel has an exact positive decision;
- all notices and restrictions are satisfied;
- no prohibited raw source/private data is included;
- output manifest and member digests validate;
- rebuild/redistribution validation passes;
- signing/publication package is separately authorized in E7.

E3-B local publication to an owned ProjectStore does not imply release eligibility.
