## Native metadata and support admission

   the augmented native /4 provenance is labeled /4 before precharge/admission.
2. Inventory projects spans from that admitted support. After the project, TOC

## Mapping, parse state and omissions

Mappings reuse `XmlInlineLua::segments()`, `map_range()` and `map_position()`.
Segments close the virtual UTF-8 byte domain in order while retaining original
XML coordinates. Identity pieces preserve literal text; XmlNewline preserves
the original CR/CRLF spelling mapped to LF; XmlEntity preserves the entire XML
entity spelling mapped to its decoded character. Comments and CDATA delimiters
remain gaps. A caret at a removed gap retains both distinct zero-width XML
boundaries, rather than one widened span or an arbitrary neighbor.

Reachable InlineBody sites require their genuine native units, including
parse-failed units. Unit semantic state and aggregate PartialFailedParse remain
retained alongside mapped diagnostics. Static source association does not inject
an implicit receiver, synthesize a callback wrapper or establish runtime
dispatch. A top-level Script's native blocking `InlineLuaNotAnalyzed` load issue
is retained with its canonical SourceOnly state; holding virtual analysis does
not promote that load result to complete.

Omissions retain the exact `ProjectXmlFactScope`, qualified document, canonical
document digest, occurrence and one typed outcome: ExternalFile, ReferenceOnly,
UnresolvedScript or UnreachableInline. They do not manufacture a virtual body
or prove absence. Original unresolved analysis, load and XML outcome streams
remain accessible through the held owners.
