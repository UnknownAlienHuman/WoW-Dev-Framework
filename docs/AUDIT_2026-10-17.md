# Technical Audit and Engineering Remediation Plan (2026-10-17)

**Status:** Normative operator mandate. Supersedes ad-hoc schema multiplication, ceremonial vertical-slice theatre, and legacy intermediate compatibility rules across all packages and issues.

---

## 1. Executive Summary

A full codebase and process audit on 2026-10-17 (`d36ba6e0`) found that the repository has grown to **~370,000 lines of Rust across 905 `.rs` files** and **~160,000 lines across 991 `.md`/`.json` files** over ~50 days (1,796 commits), while **all five launch gates (`R0`, `A0`, `A1`, `B0`, `V1`) remain `Blocked`** and the user-facing CLI, LSP, and MCP surfaces are unusable in real development environments.

Up to **70–80% of the code and runtime cost** consists of self-inflicted bureaucratic overhead:
1. Repeated JSON serialization and SHA-256 hashing inside hot loops and fixed-point convergence loops (`for _ in 0..8`, `FINALIZATION_PASSES = 6`) just to match byte-count fields embedded inside the JSON being measured.
2. Unreleased intermediate schema proliferation (`replay1..16`, `report7..11`, `source-load-proposals/19..22`, `graph-build-result/1..20`, `host1..5`), directly violating `docs/EXECUTION_MODEL.md` §7.
3. Re-parsing and re-analyzing the entire project from raw source text stored in a single SQLite JSON blob (`ProjectReplay`) on every database read (`hydrate_owner`), plus instantiating `EmmyLuaAnalysis` up to **4 times per project analysis**.
4. Massive domain-logic leakage into `crates/wow-service` (**113,300+ lines**), 7,300+ lines of duplicated `*Wire` structs in `crates/wow-context`, and 10,335 lines of code hidden behind `#![allow(dead_code)]` in `crates/wow-recognizers`.
5. Hardcoded completion blockers in `tools/xtask/src/repository/machine_state.rs` and `e3.rs` that **fail CI if any package status is changed from `pending`/`NotEvaluated` to `implemented`/`accepted`**, if real SHA-256 checksums are written to `CHECKSUMS.json`, or if implemented CLI subcommands are added to `apps/wow/CONTRACT.json`.

## 2. Package-by-Package Audit Findings

### 2.1. `crates/wow-core` (~21,186 LOC: 10,665 prod / 10,521 test)
- **Heap-heavy `CanonicalSerializer` (`crates/wow-core/src/canonical/admission.rs:48-450`)**:
  - `canonical_json_bytes` and `domain_separated_digest` are called tens of thousands of times per operation. Instead of streaming canonical JSON directly into a writer or SHA-256 hasher, `CanonicalSerializer` allocates a `BTreeMap<String, Value>` for every struct/map, clones every static field name (`key.to_owned()`, line 345), copies the `BTreeMap` into a new `serde_json::Map<String, Value>` on `finish()` (lines 307–309), and then serializes the DOM tree into a `Vec<u8>` (`canonical.rs:36`).
  - **`json_key` anti-pattern (`admission.rs:407-422`)**: To convert a single map key to a `String`, `json_key` allocates a temporary `serde_json::Map` containing `{key: true}` on the heap and extracts the key via `object.into_iter().next()`.
  - **Prohibition of `null`/`None`, `i64 < 0`, and `f64` (`admission.rs:88-130`)**: Rejecting `Option::None` and negative integers forced every downstream crate to write hundreds of `#[serde(skip_serializing_if = ...)]` annotations and custom wrapper types.
- **6x full-envelope serialization loop (`crates/wow-core/src/envelope.rs:258-277`)**:
  - `E0CheckResultDraft::finalize` embeds `budget.usage.output_bytes` (the serialized JSON byte length of the envelope) inside the hashed envelope itself. Because changing the digit count of `output_bytes` changes the JSON length and `result_id` digest, `finalize` runs up to `FINALIZATION_PASSES = 6` iterations (each doing two full canonical DOM builds), followed by `envelope.validate()` (lines 426, 444) which performs two more full passes.
- **Layer violation (`crates/wow-core/src/callable_lowering.rs` + `declarations.rs`, 998 LOC)**:
  - Contains Ketho/LuaCATS-specific `---@alias` and `---@field` lowering logic that belongs in `wow-reference` / `wow-annotations`, violating `crates/wow-core/src/lib.rs:5-6`.

## 3. Mandatory Engineering Rules (Effective Immediately)

All human and automated contributors MUST follow these rules. Any rule in older docs or issue comments that conflicts with this section is superseded.

1. **Zero Schema/Profile Proliferation (`v1` Only Pre-Release)**:
   - Do NOT create `/N+1` schema constants (`replay17`, `report11`, `host6`, `graph-build-result/21`, or 90-character capability-combination schema strings) for internal or unreleased changes.
   - Consolidate each owner onto **one** current schema version. Delete dead legacy schema tables (`STORAGE_SCHEMAS_V1..V15`, `LegacyGlobalAccessV9`, `host1..4`). Update affected fixtures directly when changing a format.
2. **Zero Multi-Pass JSON / Self-Hashing / Roundtrip Validation**:
   - Never embed the serialized byte length of a JSON payload (`output_bytes`, `delivered_page_bytes`) inside the hashed payload or cursor itself. Delete fixed-point serialization loops (`for _ in 0..8`, `FINALIZATION_PASSES = 6`).
   - Never call `serde_json::to_writer` / `charge_serialized` inside AST, XML, or graph traversal loops to meter budgets. Meter budgets using `O(1)` integer counters (node counts, input byte lengths).
   - Never implement `validate()` by cloning a structure and checking `Self::new(...) == *self` or serializing to JSON and deserializing back (`serde_json::from_slice(&serde_json::to_vec(...))`). Enforce invariants once at construction time via types.
3. **Single Analyzer Pass & True Persistence (No Re-Parse on Read)**:
   - Construct **one** `EmmyLuaAnalysis` instance per project analysis session/generation and extract syntax, call, reference, and flow facts from that single instance.
   - Never re-parse Lua/XML/TOC source files or re-run `EmmyLuaAnalysis` / graph builders when reading a persisted generation from `wow-store` (`hydrate_owner` / `validate_read_pair`). Store indexed records, graph tables, and FTS5 tables directly in SQLite (never serialize an SQLite database file as a BLOB inside another SQLite database).
4. **Strict Crate Ownership & No `*Wire` Duplication**:
   - `wow-service` is a thin orchestration facade. Do not place graph-building algorithms, XML fingerprinting, Native API joining, Reference Pack building, or LSP AST walks inside `wow-service`.
   - Derive `Serialize` and `Deserialize` directly on domain DTOs/models where wire/storage hydration is needed; delete the 7,300+ lines of duplicated `*Wire` structs in `wow-context`.
   - Delete `#![allow(dead_code)]` shadow implementations and Rube Goldberg JSON pack roundtrips in `wow-recognizers`.
5. **Standard-Compliant, Ergonomic CLI, LSP, and MCP**:
   - **CLI (`apps/wow`)**: Provide sensible defaults for all budgets, limits, and store paths, plus automatic `.toc` discovery in the working directory. Common commands (`wow check`, `wow search <query>`, `wow context map`, `wow context inspect`) must work with 0–2 arguments instead of 25–28 mandatory flags.
   - **LSP (`wow lsp`)**: Comply strictly with JSON-RPC 2.0 and LSP 3.18. Never add top-level `"wow"` fields to JSON-RPC responses; return `null` or `[]` (never `-32001`) when a position has no definition/references; accept standard client `initializationOptions` and `workspaceFolders`; remove artificial `document_symbol_disclosure` gates; connect LSP to the full project/reference/graph/rules pipeline.
   - **MCP (`wow mcp`)**: Expose real read-only project/reference/search/context/diagnostics tools by default; ignore unknown notifications per JSON-RPC 2.0 instead of exiting with code `2`; accept standard `_meta` and `cursor` fields.
6. **Clean Worktrees & Plain Technical English/Russian**:
   - Maintain a single clean worktree. Remove merged worktrees immediately after integration.
   - Write issue updates and commit messages in clear, normal prose—never in concatenated token shorthand (`Main319ca795/QuickPASS`).

## 4. Phased Remediation Roadmap

### Phase 1 — Unblock Governance, Clean Worktrees & Unify Dependencies
1. Remove the hardcoded `pending`/`NotEvaluated`/`null`-checksum traps from `tools/xtask/src/repository/machine_state.rs` and `e3.rs`, and replace per-file `git` subprocess loops in `tools/xtask/src/manifest.rs` with batch/in-process hashing.
2. Unify `emmylua_parser` and `emmylua_code_analysis` under `[workspace.dependencies]` in the root `Cargo.toml` at a single pinned revision.
3. Prune obsolete git worktrees, remove untracked scratch artifacts from the repository root, and add fast unit test execution to `.github/workflows/quick-check.yml`.

### Phase 2 — Core Performance & Persistence Repair (`wow-core`, `wow-emmy`, `wow-project`, `wow-store`)
1. Rewrite `wow-core::canonical` to stream canonical JSON without intermediate `BTreeMap`/`Value` DOM trees or `json_key` heap allocations; allow `Option`/`null`, signed integers, and floats; remove the 6-pass `finalize` loop.
2. Move `callable_lowering` from `wow-core` to `wow-reference` / `wow-annotations`.
3. Collapse the 4 `EmmyLuaAnalysis` instantiations in `wow-project::analyzer` and `wow-emmy::flow` into a single shared analysis pass; remove per-token JSON budget serialization in `shape.rs`.
4. Delete legacy replay schemas (`replay1..15`, `LegacyGlobalAccessV9`, `source-load-proposals/19..21`) and stop re-parsing/re-analyzing raw source files on SQLite reads (`hydrate_owner` / `validate_read_pair`). Store FTS5 and graph tables natively in SQLite instead of nested SQLite-in-BLOB or 3x duplicated `GraphPartitionSnapshot` JSON blobs.

### Phase 3 — Deduplicate Domain Crates & Thin Out `wow-service`
1. Delete the 10,335 lines of `#![allow(dead_code)]` modules and the in-memory JSON pack serialization roundtrip in `wow-recognizers`.
2. Delete the 7,300+ lines of duplicated `*Wire` structs in `wow-context` and fix `render_context_pack_markdown` (`crates/wow-context/src/render.rs:836-899`) to emit real human/LLM-readable Markdown instead of `\u00xx`-escaped JSON punctuation.
3. Remove the redundant legacy draft importers (`generated_api.rs`, `blizzard_api.rs`) in `wow-reference` and bypass the unnecessary `wasmi` Wasm roundtrip for `wow-ketho-literals` so enum declaration spans are preserved.
4. Move graph-build and reference-pack algorithms out of `wow-service` into their owning crates (`wow-project`/`wow-graph` and `wow-reference`), fix the schema selection bug in `crates/wow-service/src/graph/build.rs:754-790`, and unify the 4 copied pagination engines into a single generic cursor module.

### Phase 4 — Ship Usable CLI, LSP, and MCP (`apps/wow`)
1. Replace the 25–28 mandatory CLI flag parsers in `apps/wow` with ergonomic commands, sensible defaults, and automatic `.toc` workspace discovery.
2. Fix all JSON-RPC 2.0 / LSP 3.18 / MCP protocol violations in `apps/wow/src/lsp*` and `apps/wow/src/mcp*`, remove `document_symbol_disclosure` (`host1..5`), and wire full project, WoW API reference, graph, search, context, and diagnostic rules into both `wow lsp` and `wow mcp`.
