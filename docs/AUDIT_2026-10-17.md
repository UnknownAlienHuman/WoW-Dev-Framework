## 1. Scope correction — 2026-10-18

The owner clarified the product: upstream EmmyLua, native Rust Ketho annotation
processing, operation without VS Code and useful Blizzard UI/addon development.
[ADR-058](DECISIONS.md) supersedes the old E0–E7 platform requirements.

The earlier review was too conservative about retaining old readers, elaborate
pack/storage lifecycles and future acceptance work. Those requirements encouraged
more code. A real legacy caller does not establish a support commitment; it can
be removed with the current replacement. User source/configuration remains safe;
derived indexes/annotations can regenerate. Removed scope is retired, not
transferred forever between Issues.

This remains a source review with specific checked paths, not line-by-line
certification or a performance benchmark.

### Corrections that still matter

- The cited XML `type_shape.rs` vector is charged once **after** the loop; that
  code does not establish O(n²). The feature can be removed by scope decision,
  but not justified by an invented complexity claim.
- `source_signals`, `source_state`, `source_scripts`, `source_bridge` have live
  Service callers. A lint suppression does not identify dead code. Remove
  unused features through actual callers; keep needed recognizer facts.
- The optional Wasm route is not used on every annotation. #203 now explicitly
  removes it by product decision; preserve the native literal algorithm first.
- The live `generated_api.rs` importer is distinct from the removed uncompiled
  `blizzard_api.rs`. Do not delete useful ingestion because their names overlap.
- Different witness request/result labels and LSP capability/dispatch lists are
  not by themselves duplicate behavior. Collapse obsolete formats when their
  actual callers change; keep ordinary external protocol duties.
- Ketho aliases, selected inheritance/corrections, navigation and consumer probes
  already exist. The [donor map](KETHO_RUST_PORT.md) locates them. Emmy's public
  analysis APIs and private `emmylua_ls` handlers are different reuse boundaries.

## 3. Preparation delivered and next work

Earlier preparation unified two Cargo parser source identities at the same
Emmy commit, removed the orphan importer and corrected false missing-feature
claims. This scope revision removes the frozen package validators, superseded
planning directories and duplicated contributor rules; it rewrites the queue
and tasks around actual code deletions and three user workflows.

The runtime analyzer, database, pack and frontend refactors above are still
queued. They are not claimed complete by documentation edits. The PR records
actual diff/check/Quick evidence once; #191 links it. Useful parser/input tests
remain, and removed validator requirements take their own tests with them.

Protocols reviewed: [LSP 3.18](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.18/specification/),
[MCP 2025-11-25 lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)
and [JSON-RPC 2.0](https://www.jsonrpc.org/specification). These are selected
protocols, not a claim that they are the newest revisions.
