## 1. Finding and scope

The project has substantial working Rust code, but repeatedly reconstructs and
revalidates its own representations, preserves intermediate pre-release formats,
and implements lower-owner algorithms inside Service. Those are concrete
simplification targets. A file count, a lint suppression, or a pending acceptance
record does not establish that the associated implementation is disposable.

The review inspected contributor rules, architecture/dependencies, active routing,
Cargo manifests/lockfile, and the named analyzer, replay, storage, graph,
recognizer, context, frontend and repository-validator paths. It is a static
review, not a line-by-line certification of every file or a runtime benchmark.

Baseline census uses **all Git-tracked files**, counting LF bytes as lines; tests,
examples, comments and source files outside the compiled module tree are included:

| Baseline item | Files | Lines |
|---|---:|---:|
| Rust | 954 | 405,206 |
| Markdown | 722 | 123,074 |
| JSON | 269 | 38,735 |
| `crates/wow-service/**/*.rs` | 214 | 113,429 |

The root workspace has **18 members**; `bridges/literal-host` is a separate
workspace. `wow-service` accounts for about 28% of tracked Rust lines, including
its tests. This is a size observation, not a CPU or removable-code percentage.
Reproduce the inventory with `git ls-files '*.rs' '*.md' '*.json'` and per-file
line counts at the baseline. The earlier “70–80% of code and runtime cost” claim
has no supporting measurement and must not be used as a reduction target.

The [completion matrix](PROJECT_COMPLETION_MATRIX.md) retains unaccepted package
and launch gates. Existing status/check, project, graph, context, search and
selected LSP/MCP routes must not be recreated because an older document says
implementation has not started.

## 2. Verified defects and necessary corrections

### Analyzer, canonical data and persistence

- **Duplicate parser dependency — confirmed.** `Cargo.lock` contains two
  `emmylua_parser 0.29.1` package identities, using `branch=main` and `rev=...` at
  the **same** `aaaca68425d9362876228649b0b8d92f07654daa` commit. The manifests of
  `wow-emmy`, `wow-reference` and `wow-annotations` disagree about the source ID.
  Consolidation does not require an upstream upgrade.
- **Four analyzer constructions — confirmed for a particular cold path.**
  The cold path in `wow-project/src/analyzer.rs` calls syntax, member-session and
  local-flow analysis. `wow-emmy/src/flow.rs` calls member analysis again and `build_analysis`.
  Constructors are in `syntax/analyzer.rs`, `references.rs` and `flow.rs`.
  Retained-cache and `native_fact_limit` paths differ: do not describe every
  operation as constructing four analyzers. The existing `AnalyzerSession` itself
  owns two analyses; routing through that wrapper alone is insufficient. Reuse
  one analysis for the same registered input set, preserving Main/Library and
  virtual-unit ownership.
- **Repeated statement-catalog parsing — confirmed.** In
  `wow-reference/src/native_aliases.rs::ingest`, the statement branch tries
  `namespaces::read`, `function_containers::read`, then `global_colors::read`.
  Each reparses the same input with the same Emmy Lua51 configuration. Valid
  GlobalColors reaches all three after the initial lexer. The pinned
  `LuaSyntaxTree` already supplies a reusable chunk; share it within this call,
  retaining validator priority, syntax/error behavior, spans, bounds and
  cancellation. Leave isolated comment-group parsing unchanged.
  [#202](https://github.com/UnknownAlienHuman/WoW-Dev-Framework/issues/202)
  names the actual Git-catalog and annotation consumers; no new parser/cache.
- **Self-sizing canonical envelopes — confirmed.**
  `wow-core/src/envelope.rs` has `FINALIZATION_PASSES = 6` in
  `E0CheckResultDraft::finalize` and `canonical_result_order`. The operation-error
  finalizer has no size fixed point. The hashed envelope contains the serialized length used to size
  itself. `wow-search/src/entities/query/pagination.rs`, `reference/query/pagination.rs`,
  `file_set/retrieval/pagination.rs` and `federation/pagination.rs` use related
  fixed-point pagination logic. Exact delivery size belongs outside
  its own digest input; bound the final write separately.
- **Canonical allocation — confirmed; scalar-policy change is separate.**
  `wow-core/src/canonical/admission.rs` builds ordered maps and JSON values, and
  `json_key` allocates a one-entry map. It also detects duplicate keys, including
  flattened-field collisions, and handles serde's arbitrary-precision number
  protocol. Preserve those properties when removing allocations. Unconditionally
  allowing null, signed values and floats is not a performance repair; change
  the admitted scalar contract only for a concrete domain requirement.
- **Source replay on retained reads — confirmed.**
  `wow-project/src/replay/publication.rs::acquire` reads replay, calls
  `hydrate_owner`, opens the project and rebuilds graph state.
  `replay/mod.rs::hydrate_owner` reconstructs source workspaces, invokes
  `publish_initial_cancellable`, and recaptures the replay for equality.
  `validate_read_pair` also reaches source-binding reconstruction; it is not
  itself the sole analyzer/graph rebuild site. Normal retained reads need stored
  owner facts, not a cold source build disguised as hydration. The relative
  latency of a read and a cold build is **unmeasured** here.
- **Intermediate compatibility growth — confirmed.**
  `replay/mod.rs`, `replay/publication.rs` and `analyzer.rs` retain replay/schema
  tables and legacy analysis modes. Consolidate after identifying retained-data
  consumers. A one-time converter may analyze stored source; ordinary reads after
  conversion must not. Preserve source-absent reopen, or report an explicit
  migration requirement before mutating data.
  A first inventory confirms `native-project-replay/13` is still produced by
  legacy-profile recapture, read through the `wow-project.live-replay.v13`
  catalog and exercised by retained fixtures. It is not an unused label;
  [#112](https://github.com/UnknownAlienHuman/WoW-Dev-Framework/issues/112)
  carries the disposition, with conversion in #131.
- **Nested SQLite — confirmed, with additional encoding overhead.**
  `wow-store/src/search/mod.rs::build_database` serializes an FTS5 database.
  `SearchStore::prepare` hex-encodes it as `StoredSearchArtifact.database_hex`,
  wraps it in canonical JSON, and publishes it through `PendingObject` into
  `store.rs`'s `store_objects.canonical_json BLOB`. This is a SQLite image inside
  JSON inside another SQLite database. FTS5 already exists; the repair is physical
  storage/lifecycle simplification, not implementing a second search engine.
- **Repeated graph representations — confirmed; a literal threefold copy is not.**
  `wow-graph/src/partition.rs` retains foundation, producer partitions and the
  materialized graph. `partition/storage.rs` encodes these distinct records and
  re-encodes admitted records when verifying commitments. Preserve producer and
  accepted-record provenance while removing avoidable copies. Do not describe
  the records as three identical complete snapshot blobs.
- **XML quadratic-loop claim — rejected.**
  `wow-project/src/graph/xml_fingerprints/type_shape.rs` charges each current row
  inside the loop, then charges the completed vector **once after the loop**.
  This is repeated serialization, but the cited code does not establish O(n²).
  Per-event JSON accounting in `wow-emmy/src/function_calls/shape.rs` remains a
  separate, confirmed target. Keep boundedness when replacing it with counters.

### Domain boundaries and deletion candidates

- **Whole recognizer-module deletion — rejected.** `source_signals`,
  `source_state`, `source_scripts` and `source_bridge` are public modules in
  `wow-recognizers/src/lib.rs`. Service callers in `graph/build/{signals,state,
  state_core,scripts}.rs` use them. `allow(dead_code)` and worker-name comments do
  not prove dead code. Remove unreachable items individually. The W1
  `w1_pack`/matcher JSON roundtrip is a genuine simplification target, but its
  produced facts and partition support are used.
- **Context wire duplication — real consolidation opportunity, not a blind derive.**
  `wow-context/src/pack/external.rs` and `pack/external/` contain bounded external
  decoding and structural/identity checks as well as payload mirrors. Share DTO
  shapes with domain serialization where appropriate; retain fallible admission
  and owner validation. A derived `Deserialize` alone does not prove custody.
- **Markdown readability — confirmed design problem, with a safety constraint.**
  `wow-context/src/render.rs::emit_record` Unicode-escapes punctuation in quoted
  JSON/source records. Unquoted payloads use a different path. Replace those
  machine-quoted sections with readable headings, fields and bounded fenced
  source. Preserve source-as-data handling, control/bidi treatment, source spans,
  trace identity and output bounds; punctuation escaping does not by itself
  establish protection against prompt injection.
- **Reference importer deletion — only partly supported.**
  `wow-reference/src/generated_api.rs` is exported and consumed by
  `src/bin/wow-reference-api.rs` and `wow-reference-source.rs`. Retain its working
  ingestion route while consolidating normalization. The separate 829-line
  `blizzard_api.rs` has no module declaration, build/include hook, fixture or
  caller. Its embedded tests were not compiled either. The preparation removes
  that orphan; `BLIZZARD_API_REFERENCE_DRAFT.md` documents the live
  `generated_api` importer and does not require the removed file.
- **Wasm on every annotation — rejected.**
  `wow-annotations/src/selected_literals.rs` uses native rendering when no bridge
  is selected. A selected bridge supplies text and no native enum declaration
  mapping. The optional bridge, host and guest have explicit contracts in
  [ADR-057 and related decisions](DECISIONS.md). Keep the native default; evaluate
  removal of the optional lane as one dependency/consumer decision, not as an
  assumed universal runtime cost or an unexplained fallback.
- **Service domain leakage — confirmed.** `wow-service/src/graph/build/*`
  implements graph projections/fingerprints and native API joins;
  `reference_pack*.rs` includes pack algorithms. These exceed the facade boundary
  in [Architecture §§3, 18](ARCHITECTURE.md). Move one complete algorithm to its
  existing owner at a time; keep acquisition, ordering, durable effects and close
  orchestration in Service. Do not move domain semantics into Core or Store.
- **Witness request/result label asymmetry — not a demonstrated defect.**
  `GraphBuildRequest::select_component_schema` has signal/library witness labels,
  while the corresponding ordinary native-input result uses the shared
  `graph-build-result/16` envelope. `graph/bundle.rs` explicitly admits witness
  request components under that result envelope; the library-witness route in
  `local/platform_input/tests/library_witnesses.rs` exercises that composition.
  Different request and response labels do not require matching new schemas.
  Adding two result variants would break this reader unless its contract also
  changed. Keep the existing bytes; no failing producer/consumer route was
  established by the audit's label comparison.

### Frontends and completion process

- **CLI ceremony — confirmed.** `apps/wow/src/search.rs` requires nine Search
  bounds and five Store limits in addition to command-specific input and output
  arguments. Supply finite defaults and a reusable project configuration; users
  should not hand-author derived identity/evidence metadata. Automatic TOC
  discovery must produce bounded registration candidates, with flavor/variant
  ambiguity handled explicitly by the existing Project/Service owners. Update
  the low-level explicit-input contract alongside that implementation; do not
  infer trusted project identity from cwd or choose an arbitrary TOC.
- **LSP empty-result errors — confirmed.** `apps/wow/src/lsp/definition.rs` and
  `references.rs` return `-32001` for ordinary missing locations. LSP 3.18 permits
  `null`/empty results; a transport empty result is not a claim of complete
  project-wide negative authority. Preserve genuine error/cancellation cases.
  `document_symbols.rs` adds top-level `wow` metadata on empty results; remove
  this private envelope dependency. JSON-RPC's text alone does not explicitly
  ban every additional member, so the original blanket conformance claim was
  too strong. Nonempty `initializationOptions` and multiple workspace folders
  are rejected; implement or accurately negotiate the supported scope.
- **MCP interoperability — confirmed and scoped to 2025-11-25.**
  `apps/wow/src/mcp.rs` terminates on unknown notifications and rejects nonempty
  initialization `_meta`. Keep valid unsupported notifications nonfatal and
  preserve metadata as bounded opaque protocol data. The default registry is
  status-only; an opt-in context route already exists. Do not report the whole
  MCP application as absent. Finite complete lists need not be paginated; add
  cursor handling when the selected list actually needs it.
- **Frozen completion predicates — confirmed, but do not replace them with fake acceptance.**
  `tools/xtask/src/repository/machine_state.rs::common_state` requires seven owner
  pairs to remain partial/pending. E3 has separate fixed-state checks in `e3.rs`.
  Selected capability rows hardcode #120; E3 blockers are validated differently.
  These validators currently receive JSON and paths, not a verification of the
  referenced artifact bytes. Replace snapshot assertions with lifecycle and
  checksum consistency for one real owner at a time. A valid checksum is not
  full package acceptance. Keep the E0-F `status/check` list scoped to E0-F:
  it does not prohibit separately contracted context/search/graph commands.
- **Missing tests in Quick — intentional cadence, not a defect.** The operator
  requests code first and minimal Clippy during development. Keep existing tests;
  do not add per-slice test campaigns or amend Quick to contradict that instruction.
- **Documentation counts do not prove unused files.** Many files contain owner
  contracts and fixtures. Hot docs nevertheless contain false “no Rust/workspace”
  statements and closed issues presented as next work. Fix routing now; consolidate
  duplicate specifications only after preserving unique active requirements.
- **Stale donor gaps recreate code — confirmed.** The Ketho overview still called
  string catalogs, custom resources, widget inheritance and semantic probes
  missing after selected implementations existed. Current code already handles
  named/open/closed aliases, structures, namespaces, static FunctionContainer and
  GlobalColors, guarded single-parent correction, bidirectional navigation and
  synthetic dual-consumer probes. The [donor map](KETHO_RUST_PORT.md) now routes
  to those owners and retains full type/corpus/editor/consumer acceptance gaps.
- **Profile count is not duplicate behavior.** LSP synchronous/owned execution,
  host input `/1`–`/5`, and MCP baseline/registered-context scopes have real
  lifecycle or permission differences. Normalize repeated admission decisions
  internally; keep external readers until an explicit migration. The pinned Emmy
  LSP also separates capability advertisement from request dispatch. Do not
  collapse those protocol duties merely because method names appear in both.
