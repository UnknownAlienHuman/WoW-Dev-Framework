## Findings

### A01 — P1: central status and routing described an obsolete repository

Before this checkpoint, the root README sent the next agent to implement `wow-emmy`
from scratch, the completion matrix said all Rust was absent, and
`crates/MANIFEST.json` counted seven root members. Cargo actually activates fourteen,
and `wow-emmy`, project, rules, service, store, graph and recognizers have real code
and tests. Some owner READMEs and status notes also predate later commits.

Impact: repeated implementation, incorrect sequencing and false readiness/absence
claims. Fix: update central routing and machine inventory; treat owner contracts as
requirements, not current code inventories. Preserve unclosed package gates explicitly.
Future status changes must pair the actual package inventory with acceptance evidence.

### A02 — P1: required fixture-freeze gates are still open

The following existing files contain required null identities/digests and pending
freeze state despite active executable owners:

- `crates/wow-reference/examples/CHECKSUMS.json`
- `crates/wow-emmy/examples/CHECKSUMS.json`
- `crates/wow-project/examples/CHECKSUMS.json`
- `crates/wow-rules/examples/CHECKSUMS.json`
- `crates/wow-service/examples/CHECKSUMS.json`

These are normative acceptance inputs, not proof that the Rust code is absent.
Ordinary workspace tests do not close this chain automatically. Do not replace
nulls with arbitrary current hashes or rewrite expected fixtures from actual output.
First map each required case to real executable behavior, review identity/source/
canonical-output consistency, and then freeze the admitted bytes and verify them.

This checkpoint does not certify full E0 acceptance or bypass the old freeze rules.
The machine ledger separates partial executable progress from package acceptance.

### A03 — P1: an untested, inconsistent application is hidden outside the workspace

`apps/wow-reference-builder/Cargo.toml` inherits workspace settings but the root
manifest neither includes it nor designates it as an independent workspace. The
ordinary workspace CI therefore does not test its source or `tests/e1_cli.rs`.

Static source review also confirms:

- `src/lib.rs` imports `ReferenceAdminObjectId`, which is not exported by
  `wow_service::reference_admin`, and calls nonexistent `ReferenceAdminError::not_found`.
- Implemented commands are `status`, `validate`, `publish`, `read`, whereas its
  contract requires `build`, `validate`, `rebuild-compare`. Usage/I/O exit codes
  64/65 also do not implement the documented 0–8 outcome table.
- `read_bounded` checks `fs::metadata` and then calls unbounded `fs::read` on the
  path. It follows symlinks and does not bound growth during the read. A size check
  after allocation is not a bounded-read or root-confinement guarantee.

No local compiler failure is claimed: these are source-level findings plus confirmed
CI omission. Do not merely add this package to Cargo or expose its publication command.
Repair the documented application/service seam, use bounded handle-based input and
path admission, and execute actual CLI tests before activation. Keep generic storage
and object-ID details behind the service boundary.

### A04 — P1: JSON parsing accepted contradictory contract members — fixed

Before this checkpoint, `tools/xtask/src/repository.rs` parsed each JSON file into
`serde_json::Value`. Repeated object members were silently replaced: for example,
`{"implemented":false,"implemented":true}` became the latter value.

The repository check now rejects duplicate decoded keys in every object, including
objects inside arrays and equivalent escaped/Unicode keys. Independent objects may
reuse names. Strings containing structural characters remain valid. The existing
syntax, trailing-input, recursion and arbitrary-precision rules remain owned by
serde_json; the added iterative pass only checks key uniqueness.

Eight grouped regression tests cover the bypass, nesting, escaped Unicode,
independent scopes, quoted delimiters, scalar/large-number preservation, invalid
syntax/depth and data-safe duplicate diagnostics. No dependency, owner API,
Cargo.lock, fixture baseline or product behavior changed.

This is one implemented part of the handoff's contract validator. It is not a full
JSON-schema, contract-ID, fixture-coverage, dependency or Markdown-link validator.

### A05 — planned blocker: the R0 product executable is still absent

`apps/wow` contains contracts/docs, but no Cargo manifest or Rust source. The existing
service has status/check semantics over immutable normalized contexts; its
`OwnedServiceBackend` is a legitimate fixture/embedder seam, not by itself a public
CLI or proof of real owner-to-owner fixture composition.

Next work must reuse these owners, close the E0 fixture prerequisites and implement
the thin frontend. A generic store, an annotation development driver or an in-memory
graph cannot substitute for `wow status` / `wow check` acceptance.
