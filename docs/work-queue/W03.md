# W03 — Bind native Reference and Library inputs to the public local workflow

State: specified. Priority P1 / local-product critical path. Dependencies: none for implementation; W01 and W02 are safety prerequisites before accepting untrusted production inputs. Audit F03/#68. Baseline `02d893cd3b9c9dd116a3330824b9764c3d5ab919`.

## What
Let an explicitly selected materialized source/annotation result and first-party project manifest drive `wow status` / `wow check` without hand-authoring internal normalized reference and Library DTOs. Reuse the existing native Ketho pipeline and materialized-input CLI; do not create a second extractor, analyzer or public executable.

## How and files
Extend the owned conversion seam in `crates/wow-service/src/local/{input,disk_input,backend}.rs`, with narrow additions to existing reference/annotation owner APIs only where necessary. The host supplies an explicit manifest, exact source revision, environment/profile and output identities; service validates them once and constructs immutable ReferenceView and Library snapshots. Main contains only declared first-party input; full Blizzard UI implementation is never an ordinary Library. Retain raw unsupported metadata, loss/coverage reports, source maps and exact content hashes. Honor partial native reports instead of interpreting successful rendering as reference completeness. Keep `apps/wow` parsing/printing only. Managed checkout/network work is W08; full Reference Pack assembly is W06.
