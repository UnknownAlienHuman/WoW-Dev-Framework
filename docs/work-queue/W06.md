# W06 — Implement full Reference Pack service operations

State: specified. Priority P1. Integration dependencies: W03/#71 native binding and W05/#73 annotation persistence ownership. Their typed interfaces can be agreed before merges; do not wait on unrelated broad acceptance. Baseline `02d893cd3b9c9dd116a3330824b9764c3d5ab919`; audit F04/#68.

## What
Implement the normative `reference_pack_build`, `reference_pack_validate` and `reference_pack_rebuild_compare` use cases. Existing `reference_admin` validates/publishes a ReferenceView; it is not a complete Reference Pack service. Reuse real reference, annotation and store owners instead of recreating them.

## How and boundaries
Add the E1 orchestration beside `crates/wow-service/src/reference_admin.rs`, using typed requests, exact component/profile identities and bounded source/staging/destination ports. Follow preflight → reference → annotation → assembly plan → materialization → manifest → independent validation → explicit finalization. Owners produce semantic data; service composes them and owns use-case state. Reopen output to validate actual members/digests and recompute eligibility; never trust a producer's passed flag. Compare semantic/canonical/member identities independently from SQLite physical bytes. Preserve blocked/partial outcomes and license/source-map/unsupported metadata. Cancellation and response loss must produce exact recovery instructions without blind rerun or destination deletion. No generic shell, source execution, network upload, signing or implicit activation.
