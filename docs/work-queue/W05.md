# W05 — Restore the declared annotation persistence boundary

State: specified. Priority P1 contract correctness. Dependencies: none. Baseline `02d893cd3b9c9dd116a3330824b9764c3d5ab919`; audit F05/#68.

## What
Remove the unapproved regular `wow-annotations -> wow-store` dependency while preserving useful annotation artifact and persistence behavior. The E1-C contract explicitly excludes persisting SQLite/store state; this is more than a stale table entry.

## How and files
Split `crates/wow-annotations/src/persistent.rs` into pure annotation-owned artifact preparation/validation and service-owned durable orchestration. Keep semantic annotation types, canonical bytes, identity and source/projection validation in wow-annotations. Put catalog/CAS/operation/lease/GC coordination in a narrow wow-service annotation-administration module using existing generic wow-store ports. Do not move domain interpretation into wow-store or SQL into service. Retain exact persisted wire identities or implement an explicit versioned migration; preserve current objects and tests. Remove the regular Cargo edge only after callers and tests use the corrected boundary. Update Cargo.lock only for actual dependency resolution changes. Reconcile DEPENDENCY_GRAPH, MANIFEST and owned docs with the implemented seam. An alternative broader edge requires a separate reviewed ADR, not merely changing the allowed list.
