# W04 — Execute supported production WoW rule profiles

State: specified. Priority P1 / critical path. Dependency: W03 (#71) for integrated real-input acceptance; owner implementation may proceed against its agreed typed seam. Baseline `02d893cd3b9c9dd116a3330824b9764c3d5ab919`; audit F03/#68.

## What
Extend the existing API-existence and direct-local Secret/restriction rules beyond the E0 fixture profile. Ordinary exact profiles must no longer be rejected merely because they differ from FIXTURE_PROFILE_ID. Unsupported facts and profiles must still be NotEvaluated, never clean.

## How and ownership
Change `wow-rules/src/{descriptor,context,engine}.rs` to accept a versioned explicit supported-policy descriptor with exact ReferenceView, analyzer capabilities, profile identity and coverage prerequisites. Remove fixture-only namespace/partition assumptions from the production path, not from retained fixture tests. Add production dispatch in `wow-service/src/local/projection.rs` and capability reporting in the existing backend. Join exact reference lookup to analyzer observations; an unresolved analyzer symbol alone is not proof an API is absent. For the Secret rule, require exact producer facets, same-value local flow and reviewed dominance/guard semantics. Unsupported guard/type/hotfix/runtime facts remain explicit. Preserve distinct rule-selection, empty-scope and XML-semantic-unavailable outcomes. Do not implement interprocedural taint, infer Secret from names, or weaken source authority to make the feature look complete.
