# W17 — Index Blizzard UI as a separate exact source universe

State: specified. Priority P1 for context. Integration dependencies: W09/#77 load closure, W11/#79 admitted core producers and W13/#81 coherent storage. Source-profile/owner implementation can start on the existing admitted subset. Managed network acquisition W08 is not required for explicit local input. Baseline `02d893cd3b9c9dd116a3330824b9764c3d5ab919`; audit F08/#68.

## What
Implement E3-A platform-source specialization inside wow-project, reusing existing TOC/XML/Lua/analyzer/graph owners. Full Blizzard UI implementation must remain a distinct project universe, not ordinary addon Library or Reference API authority.

## How
Add typed exact materialized source/profile inputs, platform project/package identities and validated inventory/load units in wow-project. Use existing parser and analyzer plan with one exact flavor/revision/environment; classify unsupported variants and runtime conditions. Produce independently owned platform inventory/load/XML/analyzer/core-recognizer graph partitions, structural fingerprints and bounded SkeletonInputView. Publish into a separately identified logical ProjectStore through W13. Cross-universe links require exact validated owner bindings; names or similarity are not identities. Preserve source-inventory completeness separately from semantic and runtime coverage. Source/profile changes invalidate/rebind through the existing update seam; W14 supplies optimized incremental behavior, not a prerequisite for a correct initial full index. Keep source redistribution, licenses and raw excerpts explicitly controlled.
