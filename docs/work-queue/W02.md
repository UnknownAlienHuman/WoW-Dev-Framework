# W02 — Bound maintenance input before allocation

State: specified, no implementation in this PR yet. Priority P1. Dependencies: none; independent of W01/#69. Baseline `02d893cd3b9c9dd116a3330824b9764c3d5ab919`; audit F02/#68.

## What and existing code
Replace unbounded `fs::read` at external artifact ingress in `crates/wow-emmy/src/bin/wow-emmy-probe.rs` and the `wow-reference-api`, `wow-reference-topology`, `wow-reference-source` binaries. Review `tools/xtask/src/repository.rs` metadata-then-read for the same growth race. Downstream parser limits do not protect allocations already performed. The dormant builder is W07, not a reason to activate it here.

## How
For each supported artifact, derive the byte cap from its existing owner contract. Open once, inspect that handle, reject unsupported file kinds, and read through a bounded reader with at most limit + 1 bytes; reject overflow before parsing. A metadata size is an early check, not the authoritative bound. Retain exact input bytes and existing parse/digest semantics. Use small host-local helpers where semantics truly match; do not add a generic filesystem capability to core or a new crate. Existing-output comparisons must also be bounded. Do not modify successful output formats or silently truncate.
