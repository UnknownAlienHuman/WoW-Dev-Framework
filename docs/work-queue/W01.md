# W01 — Unambiguous compatibility-report admission

State: code-written / unverified. Priority P1. Dependencies: none. Audit F01 in PR #68. Continue in this branch; do not merge the specification alone.

## What
Reject repeated decoded JSON object-member names before using a compatibility report's Value projection, semantic digest, source identity or backend eligibility. Preserve the existing public API, report schema, digest definition, 64 MiB input bound and all valid existing reports.

## Existing code and ownership
`crates/wow-emmy/src/compatibility.rs::backend_identity_from_report` owns admission. `tools/xtask/src/repository.rs::validate_json` already demonstrates the bounded object-scope/member-name check, but repository validation does not cover external reports. Do not move host I/O or a generic parser framework into wow-core.

## How
Keep serde_json as the syntax, Unicode, numeric and recursion-limit authority. After successful syntax parsing, scan the original bounded bytes for object-member names, decode JSON string escapes and track uniqueness separately for each object. Reject identical and conflicting repetitions, including escaped aliases. Ignore braces, colons and escaped quotes inside value strings. Use a fixed safe InvalidJson diagnostic without echoing source values. Only after this admission may existing schema/digest/identity validation proceed.
