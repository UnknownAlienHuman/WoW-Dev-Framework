# W22 — Frontend sessions, read-only MCP and isolated local daemon

State: specified. Priority P2. Integration dependencies: W19/#87 and W20/#88 for the selected context/search registry; implementation may start with existing status/check operations. Retained-view lifecycle uses W13/#81 and W15/#83. Baseline `02d893cd3b9c9dd116a3330824b9764c3d5ab919`; audit F08/#68.

## What
Implement the shared service session/operation registry and mandatory pinned MCP stdio profile in the existing wow executable. Then implement the explicitly selected local daemon profile as a separate coherent phase; embedded MCP must not wait on optional daemon deployment. No capability is advertised before its actual transport/owner path works.

## How
Add versioned registry/session/lifecycle modules in wow-service and thin transport adapters in apps/wow. Validate exact protocol/registry/schema/profile selection, session-specific workspace/resource authorization and finite queues/budgets. MCP 2025-11-25 exposes only allow-listed implemented read/analysis operations and exact immutable resources; no generic call, model request, filesystem registration, edit, review/publication or provider proxy. Keep stdout protocol-only. Daemon uses current-user SID-ACL named pipes on Windows or mode-0600 Unix sockets, explicit endpoint identity, pinned length framing, peer authentication and isolated sessions. No TCP/network discovery. Disconnect is not cancellation; durable operation results use exact IDs/reconciliation. Final response delivery failure must not be silently dropped as progress noise. Close/drain resources in the documented order.
