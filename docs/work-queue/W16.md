# W16 — Recovery, verified backup/restore and epoch replacement

State: specified. Priority P1 data integrity. Dependencies: W13/#81 coherent publication and W15/#83 retention closure. Baseline `02d893cd3b9c9dd116a3330824b9764c3d5ab919`; audit F06/#68.

## What
Complete the missing ProjectStore recovery and maintenance operations without rebuilding the existing SQLite engine, journal, CAS or integrity checks. Provide real typed startup reconciliation, bounded verified backup, isolated restore and guarded epoch replacement.

## How and files
Extend `wow-store/src/project` and service maintenance use cases. Classify incomplete versus committed-but-unacknowledged operations by durable receipts, reconcile inactive generations, quarantine corrupt material, and never select current merely by newest timestamp. Back up a coherent held snapshot and its exact retained closure using a supported SQLite-safe method; raw copying of a live database without its required state is not a backup. Include exact manifests/digests and independently reopen/validate the result. Restore into a new isolated epoch, validate all owners, then explicitly activate under expected-current/epoch guards. Keep old readers/leases and rollback material until policy permits reclamation. Implement supported schema migrations as inactive transformations with explicit version admission, not live partial rewrites. No production restore/delete is authorized by this task.

- [ ] Windows sharing/locking and interrupted cleanup have bounded retry/report behavior.
