# W25 — Selected Windows release build and verification tooling

State: specified. Priority P2, after the usable local product. Integration dependencies: W22/#90 selected frontend registry and W16/#84 data/epoch recovery; W23/#91 only when the release profile includes LSP. Code may be developed against exact existing artifacts before full release acceptance. Baseline `02d893cd3b9c9dd116a3330824b9764c3d5ab919`; audit F08/#68.

## What
Implement the first actual E7-B source/build/artifact/bundle/support pipeline and thin internal wow-release client for one explicitly selected Windows target. This is not permission to sign, publish, install or update the user's machine. Full public channel/signing/install acceptance is a later gated stage, not implied by a local bundle.

## How
Add typed release-source/plan/build/artifact/bundle operations in wow-service behind narrow executor/materialization ports. Freeze exact source commit/tree, dependency/toolchain/target/build-script policy and bounded environment, with no arbitrary shell or caller-provided Cargo arguments. Independently validate executable self-description, member digests, licenses, SBOM/provenance and selected frontend registry; compare independent build outputs at declared logical/physical levels. Implement tools/wow-release as service-only parse/call/output code, activating Cargo only with functional commands. Each command invokes one service operation and preserves durable operation identity, OutcomeUnknown and reconciliation. Keep signing/channel/install operations unavailable unless their real separately authorized adapters and acceptance exist. Provide typed install/update/rollback plans and compatibility checks without executing them; never label a dry plan a successful installation.

## Acceptance
- [ ] Exact source/plan builds and validates one real selected Windows artifact/bundle through the service executor; unavailable toolchains are NotEvaluated, not dummy success.
- [ ] Changed source/dependency/toolchain/member/license/registry data rejects or invalidates its exact gate.
- [ ] Independent rebuild comparison, SBOM/provenance and support reports contain actual evidence, not CI/tag assertions.
- [ ] Thin client has strict bounded inputs, one-call behavior, exact output and safe broken-pipe/unknown-effect reconciliation.
- [ ] Install/update/rollback plans preserve target/data compatibility and make no applied-state claim; signing/channel effects stay unavailable without authorized implementations.
- [ ] Focused service/tool tests/check/fmt/Clippy and actual selected Windows artifact checks have exact-head evidence.
