## Findings and assigned work

### F01 — duplicate compatibility-report keys disappear before evidence validation

P1 correctness/security boundary. [compatibility.rs lines 65–130](https://github.com/UnknownAlienHuman/WoW-Dev-Framework/blob/02d893cd3b9c9dd116a3330824b9764c3d5ab919/crates/wow-emmy/src/compatibility.rs#L65-L130).

`backend_identity_from_report` parses directly into `serde_json::Value`, then computes the semantic digest and interprets compatibility/source fields. Duplicate decoded keys are already lost. A sealed report can change from `"status":"compatible"` to `"status":"incompatible","status":"compatible"` while retaining the same collapsed Value and semantic hash. Escaped spellings such as `st\u0061tus` share the same member identity.

This is ambiguity/conflict loss, **not a forged signature or demonstrated code execution**. The repository JSON checker does not protect external report import. [W01/#69](https://github.com/UnknownAlienHuman/WoW-Dev-Framework/pull/69) contains the proposed bounded original-byte member check and two Rust regressions, including seven sealed-report mutations. Its code blob `bdbc14096df61481561283ecc0abfb692679ae42` matches the locally inspected bytes. Compilation/tests remain NOT-RUN.

### F02 — maintenance commands allocate before enforcing input bounds

P1 resource safety. Locations: `crates/wow-emmy/src/bin/wow-emmy-probe.rs:28`; reference binaries `wow-reference-api.rs:68`, `wow-reference-topology.rs:78`, `wow-reference-source.rs:66,78,213`; inactive builder `src/lib.rs:251–265`.

`fs::read` loads input before downstream limits reject it. Metadata-then-unbounded-read also fails to bound a growing file. Use the opened handle and limit + 1 bounded reads before parsing, preserve each format's budget, and reject rather than truncate. No generic host/filesystem capability belongs in core. W02/#70 owns active maintenance paths; W07/#75 owns the dormant app.

### F03 — ordinary production profiles do not execute the WoW rules

P1 functional blocker. [local/projection.rs lines 330–382](https://github.com/UnknownAlienHuman/WoW-Dev-Framework/blob/02d893cd3b9c9dd116a3330824b9764c3d5ab919/crates/wow-service/src/local/projection.rs#L330-L382); `wow-rules/src/descriptor.rs:11`, `context.rs:289–295`.

The service executes WoW rules only for `FIXTURE_PROFILE_ID`; other profiles receive `unsupported_rule_profile` / `rules.profile.supported` NotEvaluated. This is honest unsupported behavior, not fake successful analysis, but blocks the ordinary-project path. Simply removing the guard is unsafe because E0 context/reference partitions are fixture-specific. W03/#71 binds real exact Reference/Library inputs; W04/#72 adds capability-gated production policies, preserving unsupported and fixture cases.

### F04 — dormant reference builder has real service and command-contract mismatches

### F05 — annotation persistence violates its declared ownership/dependency contract

P1 architecture inconsistency. `crates/wow-annotations/Cargo.toml`, `src/persistent.rs:1–18`; `crates/DEPENDENCY_GRAPH.md`, `crates/MANIFEST.json`; [E1-C non-responsibilities](../crates/wow-annotations/e1/README.md#explicit-non-responsibilities).

The regular `wow-annotations → wow-store` edge is absent from allowed edges; E1-C also explicitly excludes persisting SQLite/store state. Literal-rendering exceptions do not authorize this edge. This is not a cycle or proof that persistence is fake.

W05/#73 keeps pure annotation artifact semantics/validation in the owner and moves durable catalog/CAS/lease/operation orchestration to service over existing generic store ports, preserving identities or adding an explicit migration. An alternative wider edge requires a reviewed ADR; merely changing an allow-list is not acceptance.

### F07 — updates rebuild synchronously and cannot express every Library change

Functional/performance gap. `wow-project/src/publication.rs:164–202`; [update batch](../crates/wow-project/UPDATE_MODEL.md#7-analyzer-batch-construction), [incremental cancellation](../crates/wow-project/e2/INCREMENTAL_INVALIDATION.md#cancellationfailure).

The update route calls `build_snapshot` with a newly false cancellation flag instead of an externally cancellable incremental batch. An empty replacement-Library vector means retain old Libraries, preventing an explicit keep-versus-clear distinction. The latter is an API design gap, not an asserted failing existing test. W14/#82 defines this distinction, justified reuse/removal closure and safe old-generation preservation on failure.
